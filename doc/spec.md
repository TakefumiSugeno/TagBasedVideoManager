# システム仕様書 (System Specifications)

## 1. プロジェクト概要

### 1.1 開発背景と目的
PCのローカルストレージに保存されている動画資産を、同一LAN（Wi-Fi）内にあるスマートフォンなどのモバイルデバイスから快適に視聴するためのWebアプリケーションを構築します。
従来のフォルダ階層による管理ではなく、「FenrirFS」のような非階層型のタグ（ラベル）ベース管理システムを採用することで、動画のジャンルや出演者、メタデータに基づいた柔軟かつ高速な検索・閲覧体験を実現します。

### 1.2 コアコンセプト
- **非階層型管理**: ディレクトリ構造に縛られず、1つの動画に複数のタグを付与可能とします。
- **超軽量・シンプル**: ビルドツール（Node.js等）を排除した軽量なフロントエンドと、単一のバックエンドコンテナによるミニマルな構成とします。
- **ゼロ構成ストリーミング**: 特別なプレイヤーアプリを必要とせず、ブラウザ標準のプレイヤーで即座にシーク再生（ストリーミング）が可能であることを目指します。

### 1.3 前提条件と制限事項
- **認証とセキュリティ**: 同一LAN内でのプライベート利用を前提とするため、ユーザー認証やアクセス認可機能は持たないシンプルな構成とします。
- **対応動画フォーマット**: ブラウザが標準でネイティブ再生可能な `mp4`（映像: H.264、音声: AAC/MP3）のみを対象とします。サーバー側でのリアルタイムトランスコードは行いません。非対応フォーマットがスキャンされた場合は、ログに出力した上でデータベースへの登録をスキップします。

## 2. システムアーキテクチャ

### 2.1 技術スタック
本システムは Docker コンテナ（単一構成）での動作を前提とし、フロントエンドとAPIを同じKestrelサーバーから配信します。

| レイヤー | 技術スタック | 選定理由・役割 |
| :--- | :--- | :--- |
| **インフラ** | Docker / Docker Compose | 1コンテナで完結するシンプルなデプロイ構成 |
| **フロントエンド** | HTML5 + Alpine.js (CDN) | Node.js環境やビルド処理が不要で、HTMLに直接状態管理やインクリメンタルサーチのロジックを簡潔に記述できるため |
| **UIスタイリング** | Tailwind CSS (CDN) | CSSファイルを書かずに、クラス名のみでモバイル対応のモダンなUIを構築するため |
| **バックエンド** | F# (.NET 10) + Giraffe | 最新の.NET 10による高性能I/O。型安全でクリーンな関数型パイプライン処理 |
| **Webサーバー** | Kestrel | APIと静的ファイル(HTML/JS)の両方を高速に配信する |
| **データベース** | SQLite | ローカル運用のための軽量・単一ファイル構成 |
| **メディア処理** | FFmpeg (コンテナ内) | 動画のメタデータ取得、およびシーク用サムネイルの自動生成 |

### 2.2 配信アーキテクチャ
F# (Kestrel) の `UseStaticFiles` ミドルウェアを利用し、`wwwroot` フォルダ内に配置した `index.html`、`app.js`、`app.css` などのアセット類を直接配信します。これにより、フロントエンド用の別サーバーやコンテナが不要となり、シンプルな単一コンテナ構成を実現します。

## 3. 機能仕様（機能要件）

### 3.1 動画ライブラリの登録とディレクトリ同期
- **ディレクトリ走査**:
  - 指定された動画ディレクトリ（`VIDEO_DIR`）を再帰的に走査し、サポートされている拡張子（`.mp4`）のファイルを検出します。
  - シンボリックリンクやリパースポイントがディレクトリ構造に含まれている場合、実体パスへ解決したうえで再帰走査を継続します。
- **即時DB登録による応答性向上**:
  - ファイル検出時、フロントエンドの画面描画レスポンスを最優先とするため、ファイルシステム情報（ファイル名、相対パス、ファイルサイズ）のみで即座にデータベースへ一時登録します。
- **自動フォルダ名タグ付与**:
  - 同期時に、動画ファイルが格納されている子フォルダまでの階層パスからフォルダ名を抽出し、それぞれフラットなタグとして自動的にデータベースに登録（重複排除、デフォルト色、`ParentId = None`）して動画に自動付与します。
- **メディア生成停止処理**:
  - バックグラウンドで進行中のメディア処理（FFmpegプロセス等）を手動で停止するAPI（`POST /api/media/stop`）を呼び出すことで、処理キューを全クリアし、実行中の `ffmpeg` / `ffprobe` プロセスを安全かつ強制的に終了させます。

### 3.2 非同期メディアバックグラウンド処理
- **非同期処理キュー (MediaQueue)**:
  - データベースに即時登録された動画に対して、再生時間（メタデータ）の取得と FFmpeg によるサムネイル生成を非同期バックグラウンドキューに登録して順次処理します。
- **未作成サムネイル・未取得メタデータの自動再処理**:
  - ディレクトリ同期実行時、既存動画レコードを走査し、サムネイルファイルが存在しないかメタデータが未取得である場合、非同期キューに再投入して処理を行います。
- **無限ループ防止策**:
  - サムネイル画像パスが未登録であっても、すでにメタデータが正常に取得されている場合（`Duration > 0`）は、一度処理が失敗したものとみなし、再投入対象から除外することで無限ループを防止します。
- **高速シーク優先とフォールバックによる高速化**:
  - サムネイル生成実行時、まず `-ss` オプションを入力ファイル指定の前に置く「高速シーク（コンテナシーク）」を試みます。これにより、動画全体のデコードを発生させず瞬時にサムネイルを切り出します。
  - 高速シークで失敗（またはファイルが未生成）した場合のみ、フォールバックとして `-ss` を入力ファイルの後に置く「安全シーク（デコードシーク）」で再実行します。
- **同時実行制御と並列化・GPU支援**:
  - CPU・I/O負荷の高い `ffmpeg` はセマフォで同時実行数を1に制御します。軽量な `ffprobe` は制限から除外して並列非同期に実行します。
  - プロセス実行時、標準出力と標準エラーの非同期並行読み込みを徹底し、標準エラーバッファが埋まることによる外部プロセスのハング（デッドロック）を完全に防止します。
  - FFmpeg コマンドにハードウェアデコードオプション (`-hwaccel auto`) を付与し、ホストマシンの GPU による支援を有効化します。

### 3.3 動画の検索と分類
- **検索DSL**:
  - 検索ボックスに入力された文字列をパースし、簡易的な DSL（`tag:ツーリング`, `is:favorite`, `キーワード`）へと変換して動画検索を実行します。
  - スペース区切りによる複数条件絞り込み（AND）のほかに、明示的な `OR` 演算子（例: `tag:A OR tag:B`）を用いた論理和フィルタリングをサポートし、再帰的な親子関係タグのヒットに対応します。
- **スマートフォルダ（検索条件の保存）**:
  - 現在の検索条件（クエリ）に任意の名前を付け、データベースに永続化して「スマートフォルダ」として保存できます。保存したフォルダはサイドバーに配置され、クリックすることでいつでもその検索条件を再現適用できます。
- **親子階層タグの開閉**:
  - サイドバーのタグツリー一覧で、子を持つ親タグの横に開閉トグルボタンを配置します。折りたたまれた（閉じられた）親タグ配下の子孫タグは、ツリー構造から除外され非表示になります。

### 3.4 動画ライブラリ表示
- **表示モード**:
  - 「グリッド表示」と「リスト表示」の2つを選択・切り替えできます。
  - 大量動画の描画負荷を低減するため、件数制限付きの「ページング表示モード (20/50/100件)」と、手動でさらに追加表示する「順次追加表示（インクリメンタル）モード」を提供します。
- **カードの一定サイズ化とメタデータの常時表示**:
  - グリッドの各サイズ（小/中/大）に応じて、カード全体の高さ（例: `sm=210px`, `md=315px`, `lg=420px`）を完全に固定化し、はみ出しやレイアウト崩れを防ぎます。
  - グリッド小サイズであっても、①サムネイル、②動画タイトル、③ファイルサイズ、④登録日、⑤再生回数、⑥タグリストをすべて省略せず常時表示します。
  - タイトルコンテナの高さと line-height を完全に一致させ、テキストが領域外にはみ出して登録日やサイズなどのメタデータ表示と重なって表示されるレイアウト崩れを解消します。
- **往復等速marqueeスクロール**:
  - タイトル文字数が領域幅からはみ出している場合、ホバーしていなくても常時ゆっくり往復（marquee）スクロールさせます。
  - タイトル文字列の長さに依存せず、移動速度が常に一定（等速）になるようアニメーション期間を文字幅に応じて動的に計算します。

### 3.5 動画再生とストリーミング
- **HTTP Range Requests (HTTP 206対応)**:
  - モバイル端末等のブラウザ標準プレイヤーでのシーク再生をサポートするため、部分コンテンツ配信（HTTP Range Requests）に完全対応します。
- **スマホ再生のアプリ委譲**:
  - スマートフォンやタブレットなどのモバイル端末で閲覧している場合は、動画クリック時にブラウザ内で簡易再生するのではなく、動画ストリームの直接URLに遷移させることで、OS標準のプレイヤーや外部動画再生アプリ（VLC等）への再生委譲を可能とします。
- **シーク多重カウント防止**:
  - 動画ストリーミングの要求とは別に、動画再生開始時のみフロントエンドから専用のAPI（`POST /api/videos/{id}/access`）を呼び出して再生回数と最終アクセス日時を記録し、再生中のシーク操作による多重カウントを防止します。
- **再生回数の表示と個別クリア**:
  - 動画再生モーダルだけでなく、動画ライブラリ上の動画カードおよびリスト項目から、直接「再生回数」を確認・リセットできるゴミ箱ボタンおよびAPIを配置します。

### 3.6 再生統計・嗜好分析ダッシュボード
- **統計・おすすめ画面**:
  - フロントエンドに専用の統計ダッシュボード画面を提供します。
  - **再生数ランキング**: 再生回数が多い順の上位100件を表示します。
  - **嗜好キーワードとおすすめ**: 再生回数が1回以上の動画ファイル名から頻出するキーワードを「嗜好キーワード」として抽出し、そのキーワードを含む未再生動画を20件おすすめとして優先表示します。
  - **キーワード抽出のハイブリッド化**: 単純な記号分割ではなく、「登録済みタグ名辞書」による最優先抽出（前方・部分一致）と、「文字種境界（漢字・カタカナ・英数字・ひらがな）による分割」を組み合わせ、さらに一般的な接続語・助詞などを除外する「ストップワード辞書」を適用したハイブリッド方式で抽出します。ひらがなの名詞や未知の人名等もタグ登録されていれば漏らさず高精度に抽出されます。

### 3.7 UI/UXと共通操作性
- **モーダル誤終了防止**:
  - モーダル外クリックによるクローズ処理（`@click.away` から `@click.self` への移行など）を適正化し、モーダル上に別のモーダル（新規タグ作成等）を重ねて表示した際などに、背後のモーダルが誤って閉じられないように制御します。
- **インデントツリー**:
  - 新規タグ作成・編集時の「親タグ選択」や、自動ルールの「付与タグ選択」など、すべてのタグ選択用ドロップダウンリストにおいて、タグの親子関係（階層構造）とインデントを視覚的に反映させてツリー構造として並べて表示します。
- **サイドバー表示改善**:
  - サイドバーのタグ一覧において、各タグの右隣にそのタグが付与されている動画のユニーク件数を `(件数)` で常時右端に揃えてバッジ表示します。
  - 非ホバー時はタグ名と件数バッジが左ペインの横幅全体を最大限に活用して表示されるよう、ホバー時のみ表示される操作ボタン（ID表示、編集、削除等）を非ホバー時には物理領域を占有しない構造（`hidden` や `absolute` 配置など）にし、タグ名の表示文字数を最大化します。
- **一括設定インポート・エクスポート**:
  - タグ階層、自動ルール、スマートフォルダの設定データを、TSV（Tab-Separated Values）または JSON 形式で一括インポート登録できます。
  - 現在登録されている全設定を、インポート時と完全に同一の項目レイアウト（ヘッダー・列順）の TSV 形式または JSON 形式で一括出力（エクスポート）可能です。
  - 各項目（タグ、自動ルール、スマートフォルダ）に内部IDを表示し、IDをワンクリックでコピーできる機能を提供して管理を容易にします。
- **スマホ最適化**:
  - 画面幅が狭いモバイルサイズでは、ヘッダーのボタンテキストを非表示にしてアイコンのみとし、レイアウト崩れを防ぎます。
  - モバイル表示時は、左サイドバーをメインコンテンツを圧縮させない absolute/fixed 配置のドロワー（スライドインメニュー）形式とし、サイドバーオープン時には背景に暗い半透明のオーバーレイ（Backdrop）を配置します。

## 4. データベース仕様 (SQLite)

### 4.1 テーブル定義

SQLite上に以下の6テーブルを構築します。データベースサイズをクリーンに保つため、バックエンド起動時に `ErrorLogs` テーブルのレコードはすべて自動削除されます。

```sql
-- 1. 動画メタデータテーブル
CREATE TABLE Videos (
    Id TEXT PRIMARY KEY,
    FileName TEXT NOT NULL,
    FilePath TEXT NOT NULL UNIQUE,
    Duration INTEGER NOT NULL,
    FileSize INTEGER NOT NULL,
    ThumbnailPath TEXT,
    IsFavorite INTEGER DEFAULT 0,
    CreatedAt TEXT NOT NULL,
    AccessCount INTEGER DEFAULT 0,
    LastAccessedAt TEXT
);

-- 2. タグ管理テーブル（自己参照階層）
CREATE TABLE Tags (
    Id TEXT PRIMARY KEY,
    Name TEXT NOT NULL UNIQUE,
    ColorCode TEXT DEFAULT '#71717a',
    ParentId TEXT,
    FOREIGN KEY (ParentId) REFERENCES Tags(Id) ON DELETE SET NULL
);

-- 3. ビデオ・タグ中間テーブル（多対多）
CREATE TABLE VideoTags (
    VideoId TEXT NOT NULL,
    TagId TEXT NOT NULL,
    PRIMARY KEY (VideoId, TagId),
    FOREIGN KEY (VideoId) REFERENCES Videos(Id) ON DELETE CASCADE,
    FOREIGN KEY (TagId) REFERENCES Tags(Id) ON DELETE CASCADE
);

-- 4. 自動タグ付けルールテーブル
CREATE TABLE TaggingRules (
    Id TEXT PRIMARY KEY,
    Pattern TEXT NOT NULL,
    TagId TEXT NOT NULL,
    MatchType TEXT DEFAULT 'partial', -- prefix, suffix, partial, regex
    TargetField TEXT DEFAULT 'fileName', -- fileName, filePath, folderName
    MinSize INTEGER, -- 最小ファイルサイズ (MB)
    MaxSize INTEGER, -- 最大ファイルサイズ (MB)
    CreatedAt TEXT NOT NULL,
    FOREIGN KEY (TagId) REFERENCES Tags(Id) ON DELETE CASCADE
);

-- 5. スマートフォルダテーブル
CREATE TABLE SmartFolders (
    Id TEXT PRIMARY KEY,
    Name TEXT NOT NULL,
    Query TEXT NOT NULL,
    CreatedAt TEXT NOT NULL
);

-- 6. 例外エラーログテーブル
CREATE TABLE ErrorLogs (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Message TEXT NOT NULL,
    StackTrace TEXT,
    CreatedAt TEXT NOT NULL
);
```

| `GET` | `/api/analysis/recommendations` | 抽出キーワードとおすすめ動画（20件）を取得 | なし | `{ "keywords": ["..."], "videos": [...] }` |
| `POST` | `/api/videos/{id}/access` | 動画の再生アクセス履歴を記録する | なし | `{ "status": "recorded", "videoId": "v_1" }` |
| `POST` | `/api/videos/{id}/access/clear` | 動画の再生アクセス履歴をリセットする | なし | `{ "status": "cleared", "videoId": "v_1" }` |
| `GET` | `/api/analysis/logs` | 例外エラーログの履歴（最大100件）を取得 | なし | `[ { "id": 1, "message": "...", "stackTrace": "..." } ]` |

## 6. 環境変数と構成管理

アプリケーションの動作設定は環境変数を介して行われ、実行環境に応じて構成方法を切り分けます。

- **ローカル開発・テスト環境 (非Docker)**:
  - プロジェクトルートにある `.env` ファイルに記述されたローカル物理パスを読み込んで稼働します（`.gitignore` 対象）。
- **Docker コンテナ実行環境**:
  - ホスト側の `.env` はマウントせず、`docker-compose.yml` 内の `environment` セクションによってコンテナ専用の仮想フォルダパスを注入・代用します。

| 環境変数名 | コンテナ既定値 | 説明 |
| :--- | :--- | :--- |
| `PORT` | `5620` | Kestrelサーバーが起動するポート番号 |
| `VIDEO_DIR` | `/app/videos` | スキャン対象の動画がマウント配置されるディレクトリパス |
| `THUMBNAIL_DIR` | `/app/data/thumbnails` | 生成されたサムネイル画像の保存先ディレクトリパス |
| `DATABASE_PATH` | `/app/data/metadata.db` | SQLiteデータベースファイルの配置パス |

## 7. 品質検証・テスト仕様 (E2E / Coverage)

システムの信頼性とユーザー操作の安定性を担保するため、各種自動テストおよびコードカバレッジ収集を導入しています。

### 7.1 E2Eテスト
- **フレームワーク**: `.NET 移植版 Playwright` (`Microsoft.Playwright` / `xUnit`)
- **テスト実機**: `Chromium`（ヘッドレスモード）
- **主要なテストケース**:
  - サイドバー開閉およびレイアウト崩れの追従性
  - 検索欄入力のデバウンス動作およびクリア操作（クリアボタン、「x」ボタン）の連動性
  - 再生モーダル背景クリック制御（モーダル誤終了防止の確認）
  - スマートフォルダ、タグ階層開閉、インポート・エクスポート等の一連の Alpine.js 状態同期検証
  - テスト失敗時の、タイムスタンプおよび連番付きエラー画面自動スクリーンショット保存機能

### 7.2 カバレッジおよびエビデンス管理
- **エビデンス格納ディレクトリ**:
  - テストを実行するたびに、`test/TestResults/TestRun_yyyy-MM-dd_HH_mm_ss` 形式のタイムスタンプ付きフォルダを新規作成し、その中に成果物を集約します。
- **テストログ (TRX)**:
  - `TestRun_yyyy-MM-dd_HH_mm_ss_net10.0.trx` ファイルとして該当フォルダ内に保存されます。
- **バックエンドカバレッジ**:
  - `coverlet.MTP`（Microsoft Testing Platform 用拡張）によってCobertura形式の XML データを収集し、`ReportGenerator` ツールを介して視覚的な HTML レポートへ変換します。
  - テストの分類（Unit, Integration, E2E）ごとに個別にテストを実行してカバレッジを測定し、該当フォルダ内の `CoverageReport_Unit`, `CoverageReport_Integration`, `CoverageReport_E2E` ディレクトリへそれぞれ個別に出力します。
- **フロントエンドカバレッジ (`app.js`)**:
  - E2Eテスト中に Playwright の V8 JavaScript Coverage APIs を起動・収集します。テスト後にデータをマージし、ソースコードの行ごとの実行有無を色分け（カバー＝緑、部分カバー＝黄、未カバー＝赤）した自己完結型の HTML カバレッジレポートを、該当フォルダ内の `CoverageReport_Frontend` ディレクトリに出力します。
