# Spec Delta: companion-file-rename

## Purpose

ホストOS上の指定動画フォルダを再帰走査し、Dockerバインドマウントの制限（260文字）に抵触する長パスファイル（設定値初期値: 240文字以上、起動中一時変更可）を自動検出した上で、設定された命名規則とOpenRouterのFreeモデルを活用して短縮新ファイル名および問題発生時のAIコメントを提案し、安全に物理リネームおよびUndo（元に戻す）を行う機能を提供する。

## ADDED Requirements

### Requirement: マウント不可（パス長超過）ファイルの自動抽出と起動中閾値変更

システムは、指定されたルートディレクトリ配下の動画ファイル（.mp4等）を再帰的にスキャンし、設定ファイル（`companion-settings.json`）で定義された初期値（デフォルト: 240文字）以上のファイルを自動抽出して一覧表示しなければならない（SHALL）。また、ユーザーは起動中にUI上でこの抽出基準文字数を一時変更できなければならないが、設定ファイルへは書き戻してはならない（SHALL NOT）。

#### Scenario: 初期値による自動抽出と起動中の一時閾値変更

- **WHEN** ユーザーが「リネーム対象抽出＆AI提案を実行」を実行したとき
- **THEN** 設定ファイルの初期値（240文字）以上のファイルが抽出され、UI上で数値を変更した場合は設定ファイルを更新することなく即座に対象ファイル一覧が動的に絞り込まれること

### Requirement: 命名規則マネージャー（作成・編集・削除・並び替え・永続化）

システムは、命名規則の作成・編集・削除・優先順位並び替えが可能な管理モーダルを提供し、設定（`companion-settings.json`）のリスト先頭にあるルールを起動時の既定値として適用しなければならない（SHALL）。

#### Scenario: 命名規則の並び替えと既定ルール適用

- **WHEN** ユーザーが管理画面でルールを一番上に移動して保存したとき
- **THEN** 次回起動時にそのルールが自動選択され、AIプロンプト生成の既定として適用されること

### Requirement: OpenRouter Freeモデルによる新ファイル名および問題発生時AIコメントの提案

システムは、抽出されたファイル情報および選択された命名規則プロンプトをOpenRouterのFreeモデルに送信し、文字数上限を満たす新ファイル名候補を取得しなければならない（SHALL）。また、元のファイル名が風変わりで命名規則に従うことが困難だった場合に限り、理由・補完内容を説明する「AIコメント」を提示し、正常時はAIコメントを表示してはならない（SHALL NOT）。

#### Scenario: 風変わりなファイル名に対するAIコメント表示

- **WHEN** 元のファイル名がランダムな英数字列等で命名規則に完全に従うことが困難なファイルに対しAI提案を生成したとき
- **THEN** 正常に命名できたファイルにはAIコメントを表示せず、補完や例外対応が発生したファイルにのみ「⚠️ AIコメント」が表示されること

### Requirement: Before / After 対比プレビュー表示（上下並び・左右並び切り替え）

システムは、変更前（Before）と変更後（After）を対比表示するUIを提供し、視線移動を最小化する極低ハイトの「上下並び」と「左右並び」をトグル切り替えできなければならない（SHALL）。

#### Scenario: 上下並びでの素早い目視確認と手動修正

- **WHEN** 上下並び表示モードを選択したとき
- **THEN** 各ファイルのBefore行とAfter行、および（存在する場合のみ）AIコメントが最小限の高さで隣接して描画され、ユーザーが新ファイル名を直接テキストボックスで手動微調整できること

### Requirement: 重複回避と安全な物理リネーム実行

システムは、ユーザーが確定した新ファイル名へのリネームを実行する際、移動先ファイル名の重複チェックを行い、エラー時は安全にロールバックして結果レポートを表示しなければならない（SHALL）。

#### Scenario: 一括リネームの安全な実行

- **WHEN** ユーザーがチェックしたファイルに対して一括リネームを実行したとき
- **THEN** ホストOS上で物理ファイルがリネームされ、成功・失敗（および失敗理由）が画面上に明確にレポートされること

### Requirement: アプリ起動中リネームの Undo（元に戻す）実行

システムは、アプリ起動中に実行されたリネームの変更履歴（旧パスと新パスの対応）を保持し、ユーザーが「元に戻す」を実行した際に物理ファイルを元の名前に復元し、コンテナを再起動しなければならない（SHALL）。

#### Scenario: 直前のリネームの取り消し

- **WHEN** ユーザーが「直前のリネームを元に戻す」ボタンをクリックしたとき
- **THEN** リネームされた全ファイルが元のファイル名に逆リネームされ、Dockerコンテナが再起動されて以前の状態に戻ること

### Requirement: シンボリックリンクおよびジャンクション（リパースポイント）の追跡と安全走査

システムは、指定された走査対象フォルダ配下に存在するシンボリックリンクやディレクトリジャンクションを解釈・追跡し、その配下の動画ファイルを抽出対象に含めなければならない（SHALL）。また、同一ディレクトリへの再訪や循環参照（サイクル）を検知し、無限ループに陥ることなく安全にスキップしなければならない（SHALL）。

#### Scenario: ディレクトリジャンクション配下の動画ファイル走査

- **WHEN** 走査対象フォルダ配下に別のボリュームやディレクトリを指すジャンクションが存在するとき
- **THEN** ジャンクション配下の動画ファイルも再帰的に走査・抽出され、循環参照が存在しても安全に走査が完了すること

### Requirement: 画面要素のテキスト選択・コピー機能

システムは、走査対象フォルダパス、各ファイルのフォルダパス、変更前ファイル名などの主要なテキスト情報を、ユーザーがマウス操作で選択・クリップボードにコピー可能（Selectable）にしなければならない（SHALL）。

#### Scenario: 抽出されたパス情報のコピー

- **WHEN** ユーザーが抽出結果カード内のフォルダパスやファイル名をマウスドラッグで選択したとき
- **THEN** テキストが選択状態となり、標準のショートカット（Ctrl+C 等）でクリップボードへコピーできること

### Requirement: 抽出結果一覧のソート順指定

システムは、抽出されたファイル一覧に対しソート機能を提供しなければならない（SHALL）。既定ソートは危険度の高い「パス長 (降順)」とし、UI上で「元ファイル名 (昇順/降順)」「更新日時 (新しい順/古い順)」等に切り替え可能でなければならない（SHALL）。

#### Scenario: ソート順の変更

- **WHEN** ユーザーがツールバーでソート順を「元ファイル名 (昇順)」に切り替えたとき
- **THEN** 抽出候補カードが元ファイル名のアルファベット・五十音順で即座に並び替えられること

### Requirement: Before / After 対比プレビューの視覚的整列と等幅比較

システムは、上下並び表示においてBEFORE行とAFTER行の左側ラベル幅を固定し、ファイル名の開始X座標を垂直に完全に一致させなければならない（SHALL）。また、BEFORE行とAFTER行の高さを同一に揃え、ファイル名の比較・編集欄には同一の等幅フォント（monospace）を適用しなければならない（SHALL）。短縮文字数バッジ内の数字と文字のベースライン・上下位置を整えて表示しなければならない（SHALL）。

#### Scenario: 上下並びでのファイル名比較と整列

- **WHEN** 上下並び表示モードで候補カードを表示したとき
- **THEN** BEFORE行とAFTER行のファイル名開始位置が垂直に揃い、同一の等幅フォントおよび行高さで整然と描画され、短縮文字数バッジ内の文字と数字がガタつきなく整列して表示されること

### Requirement: 参照ボタンによるフォルダ選択ピッカー連携

システムは、対象フォルダ入力欄の「参照...」ボタンをクリックした際に、OS標準のフォルダ選択ダイアログ（`StorageProvider`）を表示し、ユーザーが選択したディレクトリパスを即座に対象フォルダ欄に反映しなければならない（SHALL）。

#### Scenario: フォルダピッカーによる走査対象ディレクトリの指定

- **WHEN** ユーザーが「参照...」ボタンをクリックしてフォルダを選択したとき
- **THEN** 選択されたフォルダのフルパスが対象フォルダ入力欄に自動設定されること

### Requirement: 命名規則マネージャーモーダルのUI表示と操作

システムは、「⚙ 管理...」ボタンをクリックした際に命名規則管理モーダルを表示し、登録された命名規則の一覧表示、新規作成、既存ルールの編集、削除、および上下並び替え（先頭ルールが既定）を行えなければならない（SHALL）。

#### Scenario: 命名規則マネージャーモーダルの開閉と操作

- **WHEN** ユーザーが「⚙ 管理...」ボタンをクリックしたとき
- **THEN** 画面前面に命名規則マネージャーモーダルがオーバーレイ表示され、ルールの追加・編集・削除・順序変更および「閉じる」操作が行えること

### Requirement: 長ファイル名表示時の親コンテナ幅維持と外枠完全描画

システムは、ウィンドウ幅を超える長大なファイル名（240文字以上）や長いAIコメント、長いディレクトリパスを表示する際、候補カード全体の青い外枠（Border）が親コンテナ幅（ウィンドウ幅）を超えて画面外へはみ出さないよう、全行で横幅クリッピングおよび親ScrollViewerの水平スクロール抑止を適用し、外枠の右端・下端が常に画面内に完全に閉じて描画されなければならない（SHALL）。また、短縮文字数バッジ（`-〇〇字 (〇〇%短縮)`）内の数字と日本語文字の上下ズレ・ベースラインの浮き沈みを排除するため、日本語と欧文のメトリクスが揃ったフォント（`Yu Gothic UI`, `Segoe UI`, sans-serif）を適用して高さを完全に一致させなければならない（SHALL）。

#### Scenario: 長大ファイル名表示時の外枠完全描画とバッジ高さ揃え

- **WHEN** 長大なファイル名および短縮バッジを上下並びカードで表示したとき
- **THEN** カードの青い外枠（Border）の右端が切れることなく完全に閉じて描画され、短縮バッジ内の数字と「字」「短縮」の文字が上下にズレることなく同一ベースライン・高さで整然と描画されること

### Requirement: .NET標準外部設定ファイル（appsettings.json / .env）からの各種設定値取得と既定命名規則および格納先パス

システムは、.NETにおける一般的な標準構成ファイル名である `appsettings.json`、環境設定ファイル（`.env`）、およびOS環境変数から各種設定値（`OPENROUTER_API_KEY`, `VIDEO_DIR`, `PATH_LENGTH_THRESHOLD`, `SelectedModel`, `Rules`）を自動取得・統合しなければならない（SHALL）。設定ファイルの探索・読み込みは、①ユーザー個別設定（`%APPDATA%\TagBasedVideoManager\appsettings.json`）、②作業ディレクトリ（`./appsettings.json`）、③実行ディレクトリ（`{AppDirectory}\appsettings.json`）、④`.env`、⑤OS環境変数、⑥組み込み既定値の順に優先適用しなければならない（SHALL）。また、GUI等で設定を永続化する際は、実行ディレクトリに既存設定がある場合はそれを更新し、それ以外は `%APPDATA%\TagBasedVideoManager\appsettings.json` へ保存しなければならない（SHALL）。設定ファイルに定義された命名規則リストの先頭ルールを、起動時のデフォルト命名規則として自動適用しなければならない（SHALL）。

#### Scenario: appsettings.json および .env からの設定読み込みと既定ルール適用

- **WHEN** AppDataまたは実行ディレクトリの `appsettings.json` や `.env` に設定値（APIキーや命名規則リスト）が記述されている状態でアプリを起動したとき
- **THEN** .NET標準の探索順序に従って外部設定値が優先ロードされ、外部ファイルで定義された先頭の命名規則が起動時のデフォルト命名規則として自動選択されること

#### Scenario: 設定変更時の標準格納先への永続化

- **WHEN** ユーザーが命名規則マネージャー等で設定を変更・保存したとき
- **THEN** 実行ディレクトリに `appsettings.json` が存在する場合はそこへ、存在しない場合は `%APPDATA%\TagBasedVideoManager\appsettings.json` へ安全に保存されること

### Requirement: OpenRouter API連携ステータスの正常化と未接続時の正直な状態管理

システムは、有効な OpenRouter API キーが設定され、実際に LLM API と通信して正常な命名提案を受信した場合にのみ「AI提案済」（青バッジ）と表示しなければならない（SHALL）。APIキー未設定時または未接続時は、プログラム内のローカル固定ロジックでAIのふりをした命名や固定コメントを生成してはならず（SHALL NOT）、バッジを「未提案」（グレー）、AFTERファイル名欄を初期状態（元ファイル名）、AIコメントを非表示（None）として保持し、画面上にAPIキー設定案内メッセージを明確に表示しなければならない（SHALL）。

#### Scenario: APIキー未設定時の未提案状態表示

- **WHEN** OpenRouter API キーが未設定の状態で「リネーム対象抽出」を実行したとき
- **THEN** 「AI提案済」とは表示されず「未提案」と明示され、勝手なAIコメントは表示されず、画面上部にAPIキー設定を促す案内バナーが表示されること
