# Spec Delta: companion-file-rename

## Purpose

ホストOS上の指定動画フォルダを再帰走査し、Dockerバインドマウントの制限に抵触または接近する長パスファイルを自動検出した上で、設定された命名規則とOpenRouterのFreeモデルを活用して短縮新ファイル名を提案し、安全に物理リネームを行う機能を提供する。

## ADDED Requirements

### Requirement: パス長超過・接近ファイルの自動抽出

システムは、指定されたルートディレクトリ配下の動画ファイル（.mp4等）を再帰的にスキャンし、絶対パスの文字数が設定された閾値（デフォルト: 220文字）以上のファイルを抽出して一覧表示しなければならない（SHALL）。

#### Scenario: 危険水準のパス長を持つファイルが抽出される

- **WHEN** ユーザーがスキャン対象フォルダを指定してスキャンを実行したとき
- **THEN** パス長が220文字以上のファイルが危険・警告バッジ付きで一覧に抽出され、現在のフルパスと文字数が表示されること

### Requirement: 命名規則・ルールの永続化とプリセット選択

システムは、命名規則設定やOpenRouter APIキー、パス長閾値をローカル設定ファイル（`companion-settings.json`）に永続化し、UI上でプリセット（「日付＋要約」「日付＋フォルダ名＋通番」等）の選択およびカスタムプロンプトの編集を行えなければならない（SHALL）。

#### Scenario: 命名規則の変更と自動保存

- **WHEN** ユーザーがUI上で命名ルールプリセットを変更するかカスタム指示を入力したとき
- **THEN** 設定がローカルJSONファイルに保存され、次回のAI提案プロンプト生成時に即時反映されること

### Requirement: OpenRouter Freeモデルによる新ファイル名の提案

システムは、抽出されたファイル名、親ディレクトリ名、作成日時、および選択された命名規則プロンプトをOpenRouterのFreeモデルに送信し、文字数上限を満たす新ファイル名候補をJSON形式で取得・提示しなければならない（SHALL）。

#### Scenario: AIによる新ファイル名候補の自動取得

- **WHEN** ユーザーが抽出されたファイルを選択して「AI提案取得」を実行したとき
- **THEN** OpenRouter APIから提案された新ファイル名が各ファイルの提案欄に反映され、新パス長が制限値内に収まっていることが表示されること

### Requirement: プレビュー表示とインライン手動編集

システムは、変更前のファイル名・パス長と、変更後の提案ファイル名・パス長を対比して確認できるグリッドUIを提供し、ユーザーが提案ファイル名を直接テキストボックスで手動修正できるようにしなければならない（SHALL）。

#### Scenario: ユーザーによる提案ファイル名の微調整

- **WHEN** ユーザーがAI提案ファイル名の入力欄を編集したとき
- **THEN** 即座に新しいパス長が再計算されてバリデーションが行われ、問題なければリネーム対象として確定できること

### Requirement: 重複回避と安全な物理リネーム実行

システムは、ユーザーが確定した新ファイル名へのリネームを実行する際、移動先ファイル名の重複チェックを行い、エラー時は安全にロールバックして結果レポートを表示しなければならない（SHALL）。

#### Scenario: 一括リネームの安全な実行

- **WHEN** ユーザーがチェックしたファイルに対して一括リネームを実行したとき
- **THEN** ホストOS上で物理ファイルがリネームされ、成功・失敗（および失敗理由）が画面上に明確にレポートされること
