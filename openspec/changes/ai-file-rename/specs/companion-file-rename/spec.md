# Spec Delta: companion-file-rename

## Purpose

ホストOS上の指定動画フォルダを再帰走査し、Dockerバインドマウントの制限（260文字）に抵触する長パスファイル（240文字以上）を自動検出した上で、設定された命名規則とOpenRouterのFreeモデルを活用して短縮新ファイル名を提案し、安全に物理リネームおよびUndo（元に戻す）を行う機能を提供する。

## ADDED Requirements

### Requirement: マウント不可（パス長超過）ファイルの自動抽出

システムは、指定されたルートディレクトリ配下の動画ファイル（.mp4等）を再帰的にスキャンし、絶対パスの文字数が240文字以上（Dockerバインドマウント制限260文字に対する安全基準）のファイルを自動抽出して一覧表示しなければならない（SHALL）。

#### Scenario: マウント不可のパス長を持つファイルが抽出される

- **WHEN** ユーザーが「リネーム対象抽出＆AI提案を実行」を実行したとき
- **THEN** パス長が240文字以上のファイルが危険ファイルとして抽出され、変更前（Before）と変更後（After）を対比確認できる一覧に表示されること

### Requirement: 命名規則マネージャー（作成・編集・削除・並び替え・永続化）

システムは、命名規則の作成・編集・削除・優先順位並び替えが可能な管理モーダルを提供し、設定（`companion-settings.json`）のリスト先頭にあるルールを起動時の既定値として適用しなければならない（SHALL）。

#### Scenario: 命名規則の並び替えと既定ルール適用

- **WHEN** ユーザーが管理画面でルールを一番上に移動して保存したとき
- **THEN** 次回起動時にそのルールが自動選択され、AIプロンプト生成の既定として適用されること

### Requirement: OpenRouter Freeモデルによる新ファイル名の提案

システムは、抽出されたファイル名、親ディレクトリ名、作成日時、および選択された命名規則プロンプトをOpenRouterのFreeモデルに送信し、文字数上限を満たす新ファイル名候補をJSON形式で取得・提示しなければならない（SHALL）。

#### Scenario: AIによる新ファイル名候補の自動取得

- **WHEN** ユーザーが抽出・提案を実行したとき
- **THEN** OpenRouter APIから提案された新ファイル名が各ファイルの提案欄に反映され、新パス長が制限値内に収まっていることが表示されること

### Requirement: Before / After 対比プレビュー表示（上下コンパクト・左右並び切り替え）

システムは、変更前（Before）と変更後（After）を対比表示するUIを提供し、視線移動を最小化する極低ハイトの「上下並び（コンパクト）」と「左右並び」をトグル切り替えできなければならない（SHALL）。

#### Scenario: 上下並びでの素早い目視確認と手動修正

- **WHEN** 上下並び表示モードを選択したとき
- **THEN** 各ファイルのBefore行とAfter行が最小限の高さで隣接して描画され、ユーザーが新ファイル名を直接テキストボックスで手動微調整できること

### Requirement: 重複回避と安全な物理リネーム実行

システムは、ユーザーが確定した新ファイル名へのリネームを実行する際、移動先ファイル名の重複チェックを行い、エラー時は安全にロールバックして結果レポートを表示しなければならない（SHALL）。

#### Scenario: 一括リネームの安全な実行

- **WHEN** ユーザーがチェックしたファイルに対して一括リネームを実行したとき
- **THEN** ホストOS上で物理ファイルがリネームされ、成功・失敗（および失敗理由）が画面上に明確にレポートされること

### Requirement: アプリ起動中リネームの Undo（元に戻す）実行

システムは、アプリ起動中に実行されたリネームの変更履歴（旧パスと新パスの対応）を保持し、ユーザーが「元に戻す」を実行した際に物理ファイルを元の名前に復元し、コンテナを再起動しなければならない（SHALL）。

#### Scenario: 直前のリネームの取り消し

- **WHEN** ユーザーが「直前のリネームを元に戻す」ボタンをクリックしたとき
- **THEN** リネームされた全ファイルが元のファイル名に逆リネームされ、Dockerコンテナが再起動されて以前の状態に戻ること
