# Spec Delta: companion-file-rename

## MODIFIED Requirements

### Requirement: スキャン直後の即時IO描画とファイルごとの非同期逐次描画・行アニメーション

システムは、ファイルスキャンが完了した直後、抽出された全ファイルを直ちに一覧として画面に描画（即時IO描画）しなければならない（SHALL）。LLMの応答を待って画面描画を保留してはならない（SHALL NOT）。その後、制御された並行数（1〜2並行）でファイル単位に非同期AI提案パイプラインを実行し、処理中の行にはインジケーター等の行アニメーションを表示しなければならない（SHALL）。各ファイルの提案が完了した時点で、該当行のアニメーションを解除して新ファイル名およびAIコメントを即座に画面へ反映（逐次更新）しなければならない（SHALL）。
**非同期パイプラインが各候補を処理する順序は、画面上に表示されている候補一覧のソート順序（`SortCriterion`、既定ではパス長降順）と完全に一致しなければならない（SHALL）。**
システムは、ディスク走査順ではなく、画面の最上部に表示されている候補から順に処理中アニメーションを表示し、ddgs検索およびLLM提案を実行・反映しなければならない（SHALL）。

#### Scenario: スキャン直後の即時一覧確認と順次アニメーション反映

- **WHEN** 「リネーム対象抽出＆AI提案を実行」をクリックしたとき
- **THEN** スキャン完了後直ちに全対象ファイルが初期状態（元ファイル名・待機中コメント）で画面に表示され、続いて処理中のファイル行にアニメーションが表示され、完了したファイルから順次新ファイル名とコメントに書き換わること

#### Scenario: 画面表示ソート順と完全一致したAI提案処理

- **WHEN** ファイル走査が完了し、パス長降順でソートされた候補一覧が画面に表示されたとき
- **THEN** 非同期パイプラインは画面の1行目（最長パスの候補）から順に処理を開始し、1行目の提案が完了した後に2行目、3行目へと画面の上から下へ順次処理が進むこと

### Requirement: 命名規則マネージャーモーダルのUI表示と操作

システムは、「⚙ 管理...」（または「⚙ 命名規則」）ボタンをクリックした際に命名規則管理モーダルを表示し、登録された命名規則の一覧表示、新規作成、既存ルールの編集、削除、および上下並び替え（先頭ルールが既定）を行えなければならない（SHALL）。
モーダルダイアログは、左右2ペイン構成（左ペイン: ルール一覧、右ペイン: ルール詳細・編集フォーム）とし、十分な視認性と作業スペースを確保するため広域サイズ（幅 960px、高さ 680px）で描画しなければならない（SHALL）。
システムは、既存ルールの優先度並び替え（「▲」「▼」）および削除（「🗑」）に加え、**既存ルールの内容編集（「✏️ 編集」）を提供しなければならない（SHALL）。**
また、ルール編集・新規作成フォームにおけるプロンプト指示文の入力エリアは、縦領域を活かした複数行テキストエリアとし、長文の指示文を見渡して編集できるようにしなければならない（SHALL）。
ルール内の「Pattern」フィールドは、ファイル抽出フィルタではなくAIに対するファイル名形式指示であることを明確化するため、UI上では「命名パターン (テンプレート):」と表記し、プレースホルダーとして `{Code}_{Summary}_{Actor}.mp4` 等の命名フォーマット例を提示しなければならない（SHALL）。

#### Scenario: 命名規則マネージャーモーダルの開閉と操作

- **WHEN** ユーザーが「⚙ 管理...」ボタンをクリックしたとき
- **THEN** 画面前面に命名規則マネージャーモーダルがオーバーレイ表示され、ルールの追加・編集・削除・順序変更および「閉じる」操作が行えること

#### Scenario: 既存ルールの選択と編集・上書き保存

- **WHEN** ルール一覧で既存ルールの「✏️ 編集」ボタンをクリックしたとき
- **THEN** 右ペインの編集フォームにそのルールの情報（ルール名、命名パターン、Web検索有効フラグ、プロンプト指示文）が読み込まれ、編集モード（「✏️ ルール編集中: 〇〇」）となること
- **WHEN** 編集フォームで内容を変更し「💾 この内容で保存」をクリックしたとき
- **THEN** ルール一覧内の該当ルールが同一の順序位置を保ったまま上書き更新され、設定ファイル（`appsettings.json`）に永続化されること

#### Scenario: ルール編集のキャンセル

- **WHEN** ルール編集モード中に「✕ 編集をキャンセル」ボタンをクリックしたとき
- **THEN** 編集中の変更が破棄され、新規ルール作成モード（空の入力フォーム）に戻ること

#### Scenario: 新規ルールの追加

- **WHEN** 左ペイン下部の「➕ 新規ルールを作成」ボタンをクリックし、右ペインでルール名およびプロンプトを入力して「💾 この内容で保存」をクリックしたとき
- **THEN** 新しいルールが一覧の末尾に追加され、設定ファイルに永続化されること

#### Scenario: 左右2ペインレイアウトと広域プロンプトテキストエリア

- **WHEN** 命名規則マネージャーモーダルを開いたとき
- **THEN** モーダルが幅960px・高さ680pxで展開され、左ペインにスクロール可能なルール一覧、右ペインに広域な編集フォームが表示され、プロンプト指示文のテキストエリアが複数行を一覧できる十分な高さを確保して表示されること
