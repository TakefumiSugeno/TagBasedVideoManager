# Proposal: renamer-rule-manager-ux

## Why

長パス動画リネーマー（Renamer）において、DuckDuckGo（`ddgs`）Web検索とLLM提案の非同期パイプライン処理順がディスク走査順のままであり、画面上の表示ソート順（パス長降順等）と不一致となってランダムな行が処理されているように見える問題がありました。
また、命名規則マネージャーでは既存ルールの編集が行えず、プロンプト指示文入力欄が48px固定で長文の指示を確認・編集しづらい上、「対象パターン」という表記がファイル抽出フィルタと誤認されやすい状態となっていました。
これらを改善し、画面表示順と同期した処理パイプラインの実現、および柔軟で使いやすい命名規則管理UIを提供します。

## What Changes

- **パイプライン処理順の画面表示順同期**:
  - `ScanCompleted` 時に、画面表示用ソート（`SortCriterion`）が適用された順序で `createAsyncPipelineCmd` を起動し、画面の最上部から順に `ddgs` 検索およびLLM提案を実行するように変更。
- **命名規則マネージャーの既存ルール編集・保存・キャンセル**:
  - ルール一覧の各カードに「✏️ 編集」ボタンを追加。
  - 既存ルールを選択して編集モードに切り替え、同じ順序位置のままルール内容を上書き保存可能にする。
  - 編集状態を破棄して新規作成モードへ戻る「✕ 編集をキャンセル」ボタンを追加。
- **モーダル子画面の左右2ペイン化＆広域テキストエリア化**:
  - モーダルサイズを広域（幅 960px / 高さ 680px）に拡張。
  - 左ペイン（幅 340px）にルール一覧、右ペイン（可変幅）にルール詳細・編集フォームを配置する左右2カラム構成に変更。
  - プロンプト指示文（AIへの指示）入力欄を縦領域いっぱいに広がる複数行テキストエリアとし、長文プロンプトも一目で見渡せるように改善。
- **命名パターンの表記適正化（案A）**:
  - ラベルを「対象パターン:」から「命名パターン (テンプレート):」へ変更。
  - ウォーターマークおよびデフォルト値を `*.mp4`（ワイルドカード誤認）から `{Code}_{Summary}_{Actor}.mp4` などの命名テンプレート例に適正化。

## Non-goals

- **拡張子・ワイルドカードによるファイル走査フィルタリング**:
  - 命名パターンをファイル抽出時の拡張子制御等には使用せず、純粋にLLMへの出力ファイル名フォーマット指示として扱う（スキャン対象は従来の動画拡張子＋パス長閾値判定を維持）。
- **マルチウィンドウ化（別Windowへの分離）**:
  - ルールマネージャーは同一ウィンドウ内のフルサイズに近い広域モーダル（左右2ペイン）として実現し、別OSウィンドウ化は行わない。

## Capabilities

### Modified Capabilities

- `companion-file-rename`:
  - ddgs Web検索およびLLM提案パイプラインの処理順序を画面の候補表示ソート順と完全同期する要件を追加。
  - 命名規則マネージャーにおける既存ルールの編集・上書き保存・キャンセル、左右2ペインレイアウト、広域複数行テキストエリア、および命名パターン表記適正化の要件を追加・更新。

## Impact

- **対象コード**:
  - `src/TagBasedVideoManager.Renamer/Domain.fs` (必要に応じた型調整)
  - `src/TagBasedVideoManager.Renamer/State.fs` (ソート順パイプライン起動、ルール編集・キャンセル状態管理・更新ロジック)
  - `src/TagBasedVideoManager.Renamer/Views.fs` (左右2ペインモーダル、広域テキストエリア、編集ボタン、ラベル修正)
- **テスト**:
  - `test/TagBasedVideoManager.Renamer.Tests/StateTests.fs` (パイプライン順序検証、ルール編集・保存・キャンセル単体テスト)
  - `test/TagBasedVideoManager.Renamer.Tests/RenameIntegrationE2ETests.fs` (画面表示順処理、ルールマネージャー新UI描画検証)
- **依存関係・外部システム**:
  - 追加の外部依存関係なし（既存の Avalonia.FuncUI および OpenRouter/ddgs 連携基盤を活用）。
