# video-scanner Spec Delta

## ADDED Requirements

### Requirement: 決定論的UUIDによる移動・リネーム・マウント変更の自動追従

システムは、動画ファイル本体を更新することなく、ファイルサイズおよびファイル内サンプリングバイト列から決定論的UUID（UUID v5）を算出してデータベースに保持しなければならない（SHALL）。スキャン時に未登録パスの動画が検出された際、旧パスに実体が存在しない既存レコードとUUID（またはUUID未設定レコードに対するサイズ・更新日時・ファイル名）で一致した場合、新規登録せず既存レコードのID・タグ・お気に入り・再生回数・再生時間を引き継いでパスとファイル名を更新し、移動先フォルダのタグを追加付与しなければならない（SHALL）。

#### Scenario: ファイル名リネーム時の同一動画引き継ぎと再処理スキップ

- **WHEN** 登録済みかつサムネイル生成・再生時間取得済みの動画ファイルが別ファイル名にリネームされてスキャンされたとき
- **THEN** 動画ファイル本体を変更することなく同一UUIDとして既存レコードが特定され、ID・タグ・お気に入り・再生回数が維持されたまま `FileName` と `FilePath` が更新され、メディア処理キューへの再投入（サムネイル再生成・動画解析）はスキップされること

#### Scenario: サブフォルダ移動時の引き継ぎと新フォルダタグ追加

- **WHEN** `FolderA/sample.mp4` として登録済みの動画が `FolderB/sample.mp4` へ移動されてスキャンされたとき
- **THEN** 既存レコードのタグ（手動タグおよび `FolderA`）と視聴履歴を維持したまま `FilePath` が更新され、新たに `FolderB` タグが追加付与されること

#### Scenario: バインドマウント変更およびUUID未設定旧レコードの移行引き継ぎ

- **WHEN** `FileUuid` が未設定の既存レコードに対してマウントパス変更後のディレクトリでスキャンが実行されたとき
- **THEN** ファイルサイズとファイル名（または更新日時）のフォールバック照合により既存レコードが特定され、算出された `FileUuid` と新パスでレコードが更新されること

#### Scenario: 元ファイルが実在する状態でのコピーファイルの独立登録

- **WHEN** 登録済み動画の元ファイルが旧パスにそのまま存在する状態で、同一内容のコピーファイルが別パスに配置されてスキャンされたとき
- **THEN** 元レコードのパスは上書きされず、コピーファイルは別の新規動画レコードとして登録されること

### Requirement: 削除済み動画レコードおよび孤児サムネイルの自動削除

システムは、有効な走査対象ディレクトリが1件以上存在するスキャン実行時において、走査およびUUID移動追従の完了後にディスク上に実ファイルが存在しないデータベース上の動画レコードを検出し、該当する動画レコード、関連するタグ紐付け、および対応するサムネイル画像ファイルを自動的に削除しなければならない（SHALL）。また、サムネイルディレクトリ内に存在するがデータベースに対応する動画IDが存在しない孤児サムネイル画像も削除しなければならない（SHALL）。

#### Scenario: 物理削除された動画のDBレコード・タグ紐付け・サムネイル一括削除

- **WHEN** データベースに登録されタグとサムネイル画像を持つ動画ファイルがディスクから削除された状態でスキャンが実行されたとき
- **THEN** 当該動画のレコード、タグ紐付け情報、およびサムネイル画像ファイル（`{VideoId}.jpg`）がすべて削除されること

#### Scenario: 孤児サムネイル画像の自動削除

- **WHEN** サムネイルディレクトリ内にデータベース上のどの動画IDにも対応しない `v_orphan01.jpg` が存在する状態でスキャンが実行されたとき
- **THEN** 当該孤児サムネイル画像ファイルが自動的に削除されること

#### Scenario: 全走査ディレクトリ不在時の誤削除防止

- **WHEN** `VIDEO_DIRS` に指定されたすべてのディレクトリが存在しない（外付けドライブ未接続等）状態でスキャンが実行されたとき
- **THEN** データベース上の既存動画レコードおよびサムネイル画像は削除されず維持されること

## MODIFIED Requirements

### Requirement: 既存動画の未処理検出と無限ループ防止

システムは、既存動画の再スキャン時、サムネイルが未作成（ThumbnailPath が None かつ現在の `THUMBNAIL_DIR/{VideoId}.jpg` を含む実ファイルが存在しない）または再生時間が未取得（Duration = 0）の動画を検出し、メディア処理キューへ再投入しなければならない（SHALL）。現在の `THUMBNAIL_DIR/{VideoId}.jpg` に実ファイルが存在する場合は、データベース上の `ThumbnailPath` が旧マウントパスであってもサムネイル存在と判定してパス文字列のみを更新し、再処理キューへ投入してはならない（SHALL NOT）。再生時間が取得済み（Duration > 0）であってもサムネイルが未作成の場合は再処理対象から除外してはならない（SHALL NOT）。また、ffprobeによるメタデータ解析に失敗した動画は既定値（120秒）等で救済してDB更新し、再スキャン時の無限滞留を防止しなければならない（SHALL）。

#### Scenario: 処理失敗レコードの再投入スキップ

- **WHEN** Duration > 0 かつ ThumbnailPath の実ファイルがディスク上に存在する既存動画のとき
- **THEN** ディレクトリ再スキャン実行時にメディア処理キューへ投入されずスキップされること

#### Scenario: バインドマウント変更によるTHUMBNAIL_DIRパス変化時の再処理スキップ

- **WHEN** Duration > 0 であり、DB上の `ThumbnailPath` は旧環境のパスを指しているが現在の `THUMBNAIL_DIR/{VideoId}.jpg` に実ファイルが存在するとき
- **THEN** メディア処理キューへ再投入されず、DB上の `ThumbnailPath` が現在の `THUMBNAIL_DIR/{VideoId}.jpg` に更新されること

#### Scenario: メタデータ解析失敗動画の救済フォールバック

- **WHEN** 破損動画等のため ffprobe の再生時間解析が失敗したとき
- **THEN** 既定再生時間（120秒）でメタデータが登録され、以降の無限再試行から除外されること

#### Scenario: サムネイル未作成レコードの再スキャン投入

- **WHEN** Duration > 0 かつ ThumbnailPath が None であり `THUMBNAIL_DIR/{VideoId}.jpg` も存在しない既存動画が存在するとき
- **THEN** ディレクトリ再スキャン実行時に当該動画がメディア処理キューへ再投入されること

#### Scenario: サムネイル実ファイル喪失レコードの再生成投入

- **WHEN** DB上 ThumbnailPath が設定されているがディスク上（`ThumbnailPath` および `THUMBNAIL_DIR/{VideoId}.jpg`）に実ファイルが存在しないとき
- **THEN** ディレクトリ再スキャン実行時に再処理が必要と判定され、メディア処理キューへ投入されること
