# video-library Spec Delta

## MODIFIED Requirements

### Requirement: HTTP Range Requests (HTTP 206) による動画ストリーミング配信

システムは、`GET /api/videos/{id}/stream` の Range ヘッダーを解釈し、指定範囲のバイナリと HTTP 206 Partial Content を返却しなければならない（SHALL）。物理ファイル不在時は HTTP 500 例外を発生させず、直ちに HTTP 404 Not Found とエラー詳細 JSON（`FILE_NOT_FOUND`）を返却しなければならない（SHALL）。また、Linux 環境等においてファイル名がカーネル制限（`NAME_MAX` 255バイト）を超過している場合、ストリーミング前にファイル名単体の UTF-8 バイト数を検査し、直ちに HTTP 422 とエラーコード `FILE_NAME_TOO_LONG` を含む JSON を返却しなければならない（SHALL）。実行中に `PathTooLongException` 等の関連例外が発生した場合も HTTP 500 クラッシュさせず（SHALL NOT）、安全に捕捉して HTTP 422 JSON を返却しなければならない（SHALL）。クライアント切断（`OperationCanceledException`）時はエラーログを記録せず静かに終了しなければならない（SHALL）。

#### Scenario: シーク再生時の部分コンテンツ要求

- **WHEN** クライアントから Range ヘッダーを含む動画ストリーム要求が送信されたとき
- **THEN** サーバーは HTTP 206 と共に Content-Range ヘッダーおよび要求範囲の動画バイナリを返却すること

#### Scenario: 実ファイル消失時の 404 エラー応答

- **WHEN** DBに登録されているが物理ストレージ上に実ファイルが存在しない動画のストリームが要求されたとき
- **THEN** サーバーは HTTP 500 エラーとならず HTTP 404 Not Found とエラーメッセージ JSON を返却し、クライアントに動画ファイルが存在しないことを通知すること

#### Scenario: Linuxファイル名長制限超過時のFail-Fast HTTP 422と専用エラーコード返却

- **WHEN** ファイル名が Linux の 255 バイト制限を超過している動画に対してストリーミング配信が要求された時
- **THEN** サーバーは 500 エラーにならず、HTTP 422 と `{"code": "FILE_NAME_TOO_LONG", "error": "ファイル名が Linux の 255 バイト制限 (NAME_MAX) を超過しているため再生できません。"}` を返却する

#### Scenario: クライアント切断時の正常終了

- **WHEN** 動画再生中にクライアントが接続を切断（タブ閉じ・シーク）してキャンセルされた時
- **THEN** サーバーは未処理例外として 500 エラーログを記録することなく静かに処理を完了すること

### Requirement: ストリーミングエラー時のフロントエンド詳細通知とオーバーレイ表示

フロントエンド（Web UI）は、動画プレイヤー（`<video>`）におけるストリーミング再生エラー（`@error`）を検知した際、ストリーミングエンドポイントへ非同期リクエストを発行してステータスコードおよびエラーレスポンスを解析しなければならない（SHALL）。ファイル名長制限（`FILE_NAME_TOO_LONG`）を検知した場合は、赤色トースト通知を表示するとともに、プレイヤー画面領域の中央にエラーオーバーレイを表示し、ファイル名が Linux の 255 バイト制限を超過している旨、該当ファイルのパス、および「ファイルパスをコピー」ボタンを表示して AI File Renamer 等での短縮リネームを案内しなければならない（SHALL）。また、物理ファイル不在（HTTP 404 `FILE_NOT_FOUND`）を検知した場合は、「動画ファイルが見つかりません」を含む赤色エラートースト通知およびプレイヤー内エラーオーバーレイ（対象ファイルパス表示・スキャン同期実行ボタン・閉じるボタン）を表示しなければならない（SHALL）。その他のストリーミングエラー発生時にもエラートースト通知を表示しなければならない（SHALL）。

#### Scenario: FILE_NAME_TOO_LONG発生時のトースト通知とプレイヤーオーバーレイ表示

- **WHEN** ユーザーが動画一覧から Linux 255バイト制限超過の動画をクリックして再生を開始し、ストリーミングが HTTP 422 で失敗した時
- **THEN** 画面上に「⚠️ 再生エラー: ファイル名が Linux の 255 バイト制限を超過しています」の赤色トースト通知が表示され、プレイヤー中央に「再生できません / ファイルパスをコピー」を含むオーバーレイメッセージが表示される

#### Scenario: 物理ファイル不在（HTTP 404）発生時のエラートースト通知とオーバーレイ表示

- **WHEN** スキャン実行前に削除または移動された動画をユーザーがクリックして再生を開始し、ストリーミングが HTTP 404 で失敗した時
- **THEN** 画面上に「動画ファイルが見つかりません」を含む赤色エラートースト通知およびプレイヤー中央のエラーオーバーレイ（ファイルパスとスキャン同期実行導線を含む）が表示されること

#### Scenario: 通常のエラー発生時のトースト通知

- **WHEN** ネットワーク切断やサーバー異常等で通常のストリーミングエラーが発生した時
- **THEN** 画面上に適切なエラー内容のトースト通知が表示される
