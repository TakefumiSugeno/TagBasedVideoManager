# Spec Delta: companion-file-rename

## MODIFIED Requirements

### Requirement: OpenRouter Freeモデルによる新ファイル名および問題発生時AIコメントの提案

システムは、抽出されたファイル情報および選択された命名規則プロンプト（Web検索結果を含む）をOpenRouterのモデルに送信し、文字数上限を満たす新ファイル名候補を取得しなければならない（SHALL）。また、正常時・例外時を問わず、命名の意図・根拠・短縮内容（またはWeb検索結果の反映内容）を説明する「AIコメント」を必ず生成・保持し、常時表示しなければならない（SHALL）。

#### Scenario: 風変わりなファイル名に対するAIコメント表示

- **WHEN** 元のファイル名がランダムな英数字列等で命名規則に完全に従うことが困難なファイルに対しAI提案を生成したとき
- **THEN** 正常に命名できたファイルも含め、補完・例外理由や短縮根拠を説明するAIコメントが生成され、常時表示されること

#### Scenario: 通常短縮時およびWeb検索補完時のAIコメント常時表示

- **WHEN** ユーザーが抽出されたファイルに対してAI提案を実行したとき
- **THEN** 正常に命名できたファイルも含め、すべての提案ファイルに対して命名根拠・短縮理由を説明するAIコメントが生成され、常時表示されること

### Requirement: Before / After 対比プレビュー表示（上下並び・左右並び切り替え）

システムは、変更前（Before）と変更後（After）、およびAIコメントを対比表示するUIを提供しなければならない（SHALL）。各ファイル候補カードにおいて、「旧ファイル名 (BEFORE)」「新ファイル名 (AFTER)」「AIコメント (AI COMMENT)」の3行を常時固定表示しなければならない（SHALL）。

#### Scenario: 上下並びでの素早い目視確認と手動修正

- **WHEN** 上下並び表示モードを選択したとき
- **THEN** 各ファイルのBefore行とAfter行、および常時表示されるAIコメント行が最小限の高さで隣接して描画され、ユーザーが新ファイル名を直接テキストボックスで手動微調整できること

#### Scenario: 3行常時表示による素早い目視確認と手動修正

- **WHEN** 候補一覧を表示したとき
- **THEN** 各候補カード内に「BEFORE行」「AFTER行」「AI COMMENT行」の3行が常に描画され、未提案状態ではプレースホルダー、提案完了後は新ファイル名とAIコメントが整然と表示されること

## ADDED Requirements

### Requirement: DuckDuckGo Search (ddgs) による Web 検索コンテキストの LLM 注入

システムは、命名規則（`NamingRule`）においてWeb検索が有効化されている場合、Pythonスクリプト（`scripts/ddgs_search.py`）を呼び出してDuckDuckGo（`ddgs`）から作品・タイトルに関する検索結果（上位スニペット）を取得し、LLMプロンプトに検索コンテキストとして付与した上で新ファイル名を提案しなければならない（SHALL）。また、実行環境にPythonまたは `ddgs` ライブラリが存在しない場合、あるいは通信エラーが発生した場合は、アプリを異常終了させてはならず（SHALL NOT）、Web検索を安全にスキップして通常プロンプトでLLM問い合わせを継続し、AIコメントにスキップ理由を明記しなければならない（SHALL）。

#### Scenario: Web検索有効ルールでの正式名称特定と提案

- **WHEN** Web検索が有効な命名規則を選択してAI提案を実行したとき
- **THEN** ファイル名から検索キーワードが抽出されて `ddgs` によるWeb検索が行われ、その検索結果を参考にしてLLMが正確な作品名を含む新ファイル名とAIコメントを提案すること

#### Scenario: Python/ddgs未導入時の安全なフォールバック

- **WHEN** Python環境または `ddgs` ライブラリが利用できない環境でWeb検索有効ルールを実行したとき
- **THEN** エラーで処理を中断することなくWeb検索のみを安全にスキップし、LLMによる通常提案が行われ、AIコメントにWeb検索スキップの旨が記録されること

### Requirement: スキャン直後の即時IO描画とファイルごとの非同期逐次描画・行アニメーション

システムは、ファイルスキャンが完了した直後、抽出された全ファイルを直ちに一覧として画面に描画（即時IO描画）しなければならない（SHALL）。LLMの応答を待って画面描画を保留してはならない（SHALL NOT）。その後、制御された並行数（1〜2並行）でファイル単位に非同期AI提案パイプラインを実行し、処理中の行にはインジケーター等の行アニメーションを表示しなければならない（SHALL）。各ファイルの提案が完了した時点で、該当行のアニメーションを解除して新ファイル名およびAIコメントを即座に画面へ反映（逐次更新）しなければならない（SHALL）。

#### Scenario: スキャン直後の即時一覧確認と順次アニメーション反映

- **WHEN** 「リネーム対象抽出＆AI提案を実行」をクリックしたとき
- **THEN** スキャン完了後直ちに全対象ファイルが初期状態（元ファイル名・待機中コメント）で画面に表示され、続いて処理中のファイル行にアニメーションが表示され、完了したファイルから順次新ファイル名とコメントに書き換わること

### Requirement: 新ファイル名 (AFTER) 行の緑色背景と文字数抵触時の部分警告表示

システムは、新ファイル名（AFTER）行を緑色（エメラルド基調）をベースとして描画しなければならない（SHALL）。新ファイル名のフルパス文字数が現在の抽出基準文字数（閾値）以上である場合（文字数抵触時）、AFTER行の左端ラベルバッジ「AFTER (〇〇字 [危険])」の背景色のみを赤色（危険色）に変更して明示的に警告しなければならない（SHALL）。基準文字数未満（安全）である場合は、同ラベルバッジを緑色（安全色）で「AFTER (〇〇字 [安全])」と表示しなければならない（SHALL）。

#### Scenario: 文字数抵触時におけるAFTERラベルバッジの赤色警告表示

- **WHEN** 提案された（または手動編集された）新ファイル名のパス文字数が抽出基準文字数（閾値）以上であるとき
- **THEN** AFTER行の全体は緑色基調を保ちつつ、左側の「AFTER (〇〇字 [危険])」ラベルバッジの背景色のみが赤色で強調表示されること

#### Scenario: 安全文字数達成時におけるAFTERラベルバッジの緑色表示

- **WHEN** 新ファイル名のパス文字数が抽出基準文字数未満となったとき
- **THEN** 左側の「AFTER (〇〇字 [安全])」ラベルバッジの背景色が緑色で表示され、安全であることが明確に視認できること
