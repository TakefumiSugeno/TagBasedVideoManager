# 申し送り事項 (Handover): DuckDuckGo Web検索連携 & 非同期逐次提案パイプライン (`ddgs-async-rename`)

## 1. 概要

本ドキュメントは、長パス動画ファイルのリネーム精度向上とUX改善を目的とした変更 **`ddgs-async-rename`** に関する実装結果、設計決定事項、既知の課題、および今後の運用・拡張性を整理した申し送り書です。

---

## 2. 実装完了のサマリ

- **アーキテクチャ**: F# 100% (.NET 10) + Avalonia.FuncUI (Elmish MVU) + Python 3 (`ddgs`)
- **Web検索連携 (`ddgs`) 基盤**:
  - `scripts/ddgs_search.py`: DuckDuckGo Search ライブラリ (`ddgs`) を用いて作品名・タイトルの上位スニペットを検索し、JSON形式で標準出力するスタンドアロンスクリプト。
  - `WebSearchClient.fs`: F# から非同期プロセスとして Python スクリプトを実行。Python未導入環境や検索エラー時にはクラッシュせず安全にスキップ（通常プロンプトへ自動フォールバック）し、AIコメントにスキップ理由を記録。
  - `Domain.fs`, `Settings.fs`: 命名規則 (`NamingRule`) に `EnableWebSearch: bool` を新設し、ルールごとに検索連携の有効/無効を永続化。
- **OpenRouterClient & AIプロンプト生成の拡張**:
  - 単一ファイル提案API `requestSingleProposal`: Web検索スニペットを注入したプロンプトを構築し、JSONレスポンスを厳格パース。
  - AIコメントの常時保持: 正常時・例外時を問わず、すべての提案に対して命名根拠・短縮理由を説明するAIコメントを生成・保持（空やnull時もデフォルトコメントを補完）。
- **即時IO描画と非同期逐次提案パイプライン**:
  - 即時IO描画: スキャン完了直後、抽出された全ファイルを「初期状態（元ファイル名・待機中コメント）」で直ちに画面一覧に描画。LLM応答待ちによる画面フリーズ・待機時間をゼロ化。
  - ファイル単位非同期パイプライン: 並行度制御（1〜2並行）を適用し、1件ずつ `CandidateAiProcessing`（処理中開始）→ `CandidateAiProposed`（提案反映）を dispatch してリアルタイムに逐次更新。
  - キャンセル機構: ツールバーの「⏹ 中止」ボタン（`CancelAiProposal`）により `CancellationTokenSource` で即時キャンセル。また、提案処理中であっても新条件（フォルダ・閾値・ルール）で「⚡ 抽出＆AI提案を実行」をクリックした場合は、先行タスクを自動キャンセルして新しい条件で即座に再スタート可能。
- **UI/UXの刷新 (HTMLモック `mockup.html` の忠実再現)**:
  - 3行常時固定表示レイアウト: 縦型・横型両カードにおいて「旧ファイル名 (BEFORE)」「新ファイル名 (AFTER)」「AIコメント (AI COMMENT)」の3行を常時固定表示。未提案時はプレースホルダー、提案後は新ファイル名とAIコメントを整然と配置。
  - 処理中行アニメーション: 処理中の行（`IsAiProcessing = true`）にプログレスバー / インジケーター（`⠋ 🌐 DuckDuckGo (ddgs) 検索・LLM提案を実行中...`）をアニメーション表示。
  - AFTER行の緑色基調 & ラベル赤化警告: AFTER行はエメラルドグリーン基調とし、パス文字数閾値（240字等）抵触時は左側ラベルバッジ「AFTER (〇〇字 [危険])」の背景色のみを赤色（`#450a0a` / `#ef4444`）に変更して警告。
  - フッター制御（パターンA）: AI提案中（`IsRequestingAi = true`）はリネームボタン群を非活性化（Disabled）し、中央に進捗バッジ（`🤖 AI提案中... (〇/〇件完了)`）を表示して誤リネームを防止。
  - ユーザー指摘のUIデグレ防止: AIモデル選択 ComboBox の順序安定化と設定永続化、命名規則マネージャーにおける新規ルール追加フォーム・保存処理を完備。
- **テスト自動化 & 品質エビデンス**:
  - 全単体テスト・結合テスト・E2Eテスト: **全150件 100% 成功**（Renamer 84件, Backend 66件）。
  - GUI実画面レンダリング検証: `HostWindow` 経由で非同期処理中インジケーター、フッター進捗バッジ、3行常時表示、中止ボタン活性化、リネームボタン非活性化の描画アサーションを自動検証。
  - TRX テストレポート: `test/TestResults/TestRun_2026-09-30_03_55_03/` に Renamer および Backend のエビデンスを出力。

## 3. 既知の課題・技術的負債

### 3.1 Python実行環境および `ddgs` ライブラリの有無

- **内容**: Web検索連携を実際に機能させるには、ホストOS上に Python 3 および `duckduckgo_search` (`ddgs`) パッケージがインストールされている必要があります。
- **対応状況**: Python または `ddgs` が存在しない環境でも、`WebSearchClient.fs` が安全に `Error` を検知して Web 検索をスキップし、通常のプロンプトで LLM 提案を継続するフォールバック処理を実装済みです。
- **今後の推奨**: 初回起動時や設定画面において、Python / ddgs 環境の検出状態を表示するステータスインジケーターを追加するとより親切になります。

### 3.2 大量ファイル処理時の外部API負荷

- **内容**: 走査対象ファイルが数百件規模となった場合、ファイルごとの逐次非同期呼び出しにより OpenRouter API および DuckDuckGo のレートリミットに達する可能性があります。
- **対応状況**: 現在は並行度1〜2の制御（セマフォ/逐次処理）を適用しており、短時間のスパイクを抑制しています。
- **今後の推奨**: 50件以上のファイルを一度に処理する際は、バッチ処理への自動切り替えやリトライ待機（Exponential Backoff）の導入を検討。
