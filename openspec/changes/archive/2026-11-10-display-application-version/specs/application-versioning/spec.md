# Spec Delta: application-versioning

## Purpose

Webアプリケーションおよびデスクトップアプリケーションにおいて、稼働バージョンの一意な識別、トラブルシューティングの迅速化、および変更規模に応じた一貫性のあるバージョン管理を実現するため、セマンティックバージョニング採番規則、バージョン配信API、およびUI画面上でのバージョン表示機能を提供する。

## ADDED Requirements

### Requirement: セマンティックバージョニング規則の準拠と独立管理

システムは、Web アプリケーションおよびデスクトップアプリケーション（AI File Renamer）において、SemVer 2.0.0（`X.Y.Z` 形式）に基づく独立したバージョン管理を行わなければならない（SHALL）。各桁の増分規則は、`X`（メジャー）を互換性のない破壊的変更（L3）またはユーザーからの明示的な指示、`Y`（マイナー）を後方互換性のある新機能追加・機能改善・仕様変更（L2）、`Z`（パッチ）を不具合修正・軽微な調整（L1）としなければならない（SHALL）。また、本機能導入時の初期バージョンは双方 `0.1.0` としなければならない（SHALL）。

#### Scenario: 初期バージョンの定義と独立性

- **WHEN** システムのバージョン管理が導入された初期状態において
- **THEN** Web アプリケーションおよびデスクトップアプリケーションの各プロジェクト定義に独立して `0.1.0` が設定されていること

#### Scenario: 変更規模またはユーザー指示に応じたカウントアップ

- **WHEN** OpenSpec において L2 規模の変更が適用された時
- **THEN** 対象アプリケーションの `Y`（マイナー）が 1 増加し、`Z` が 0 にリセットされること
- **WHEN** ユーザーから明示的なメジャー更新指示があった時
- **THEN** 対象アプリケーションの `X`（メジャー）が 1 増加し、`Y` および `Z` が 0 にリセットされること

### Requirement: Web バックエンドによるバージョン情報の API 配信とキャッシュ制御

システムは、稼働中の Web アプリケーションのバージョン情報を提供するエンドポイントとして `GET /api/version` を公開しなければならない（SHALL）。本エンドポイントは、プロジェクトアセンブリからセマンティックバージョン文字列（`+` 以降のコミットハッシュ等はサニタイズして除去）を取得し、`version` プロパティに格納した JSON オブジェクト（HTTP 200 OK）として即座に返却しなければならない（SHALL）。また、コンテナ更新後にブラウザが古いバージョンを保持し続けないよう、レスポンスヘッダーに `Cache-Control: no-cache, no-store, must-revalidate` を付与しなければならない（SHALL）。アセンブリバージョン取得で予期せぬ例外が生じた場合は、HTTP 500 で停止せず安全なフォールバックバージョン（`"0.0.0"`）を返却しなければならない（SHALL）。

#### Scenario: 稼働バージョンの正常取得とキャッシュ抑止

- **WHEN** クライアントが `GET /api/version` にリクエストを発行した時
- **THEN** HTTP 200 OK、`Cache-Control: no-cache, no-store, must-revalidate` ヘッダー、および `{"version": "0.1.0"}` を含む JSON が返却されること

#### Scenario: ヘルスチェックや認証不要の軽量アクセス

- **WHEN** 認証セッションやクッキーを持たない任意のクライアントが `GET /api/version` を呼び出した時
- **THEN** 外部依存性やデータベースアクセスを介さず、即座にバージョン JSON が返却されること

#### Scenario: コミットハッシュのサニタイズ

- **WHEN** .NET SDK によりアセンブリバージョンに `0.1.0+abcdef123` 等のメタデータが付加されている場合
- **THEN** `+` 以降が除去され、純粋な SemVer 文字列 `"0.1.0"` として返却されること

### Requirement: Web フロントエンド画面ヘッダーでのバージョンバッジ表示と耐障害性

Web フロントエンドは、画面初期化時に `/api/version` を独立した非同期タスクとして短時間タイムアウト（2秒以内）付きで取得し、画面ヘッダー内のアプリケーションタイトルの右横に `v{version}` 形式の静的ピルバッジを描画しなければならない（SHALL）。バージョン取得処理は、動画一覧やタグ一覧等のコアデータの初期化処理を一切ブロックしてはならない（SHALL）。画面幅 768px 未満のモバイル表示においてタイトルが複数行に折り返された場合でも、バッジがタイトルの末尾に自然に追従してインライン表示されなければならない（SHALL）。また、ブラウザのウィンドウ／タブタイトル（`<title>`）にもバージョン文字列を反映しなければならない（SHALL）。

#### Scenario: デスクトップ環境でのヘッダーバッジ表示

- **WHEN** ユーザーがデスクトップブラウザで Web 画面を開いた時
- **THEN** ヘッダーのアプリ名右横に `v0.1.0` のピルバッジが表示され、タブタイトルが `Tag-Based Video Manager (v0.1.0)` となること

#### Scenario: モバイル画面での折り返し時表示

- **WHEN** 画面幅 768px 未満のモバイル端末においてタイトルテキストが折り返された時
- **THEN** バッジが画面外へ突き抜けたりアクションアイコンと衝突することなく、タイトル文字列の末尾にインラインで追従して表示されること

#### Scenario: API 取得失敗・ハング時のコア機能維持とフォールバック

- **WHEN** ネットワーク切断、500エラー、または 2 秒以上のタイムアウトにより `/api/version` の取得に失敗した時
- **THEN** 動画一覧やタグ一覧の描画がブロックされず通常通り利用可能であり、ヘッダーのバッジは視覚的な破綻を起こさず安全に非表示となり、ブラウザコンソールに警告ログが出力されること

### Requirement: デスクトップアプリのウィンドウタイトルバーでのバージョン表示と起動ログ

デスクトップアプリケーション（AI File Renamer）は、自身のアセンブリメタデータからバージョンを取得（コミットハッシュはサニタイズ）し、メインウィンドウのタイトルバー（`base.Title`）に `TagBasedVideoManager - AI File Renamer v{version}` を設定・表示しなければならない（SHALL）。また、起動時にコンソールまたはログへ稼働バージョンを出力しなければならない（SHALL）。メインウィンドウ内の描画領域にはバージョン用の追加ヘッダーを設けず、既存のコントロールパネルおよびファイル比較領域の広さを維持しなければならない（SHALL）。アセンブリバージョン取得失敗時はフォールバックとして `"0.0.0"` を用いて安全に起動しなければならない（SHALL）。

#### Scenario: デスクトップ起動時のタイトルバー表示とログ出力

- **WHEN** ユーザーが AI File Renamer を起動した時
- **THEN** ウィンドウ上部のタイトルバーに `TagBasedVideoManager - AI File Renamer v0.1.0` が表示され、起動ログにバージョンが出力されること
