## MODIFIED Requirements

### Requirement: ディレクトリ再帰走査とリパースポイント追跡

システムは、環境変数 `VIDEO_DIRS`（`;` 区切り）で指定された全ての動画ディレクトリ配下を再帰的に走査し、対応拡張子（`.mp4`）の動画ファイルを検出しなければならない（SHALL）。また、シンボリックリンクやジャンクションが存在する場合、実体パスを解決して走査を継続しなければならない（SHALL）。指定された一部のディレクトリが存在しない場合は、そのディレクトリのみを警告ログ付きでスキップし、残りのディレクトリの走査を継続しなければならない（SHALL）。全ディレクトリが存在しない場合もエラーとせず 0 件として安全に終了しなければならない（SHALL）。

#### Scenario: 通常ファイルおよびシンボリックリンク配下の動画検出

- **WHEN** スキャン処理が実行されたとき
- **THEN** 各ルートフォルダおよびシンボリックリンク先のすべての `.mp4` ファイルが検出されること

#### Scenario: 存在しないディレクトリの安全走査

- **WHEN** `VIDEO_DIRS` の全ての要素が存在しない状態でスキャンが実行されたとき
- **THEN** 例外終了せず、走査結果 0 件（`Ok 0`）として安全に処理を完了すること

#### Scenario: 複数物理フォルダの動画検出

- **WHEN** `VIDEO_DIRS` に 2 つの物理フォルダ（それぞれ `.mp4` を含む）を指定してスキャンが実行されたとき
- **THEN** 両フォルダ配下のすべての `.mp4` ファイルが検出され DB に登録されること

#### Scenario: 一部ディレクトリが存在しない場合の継続走査

- **WHEN** `VIDEO_DIRS` の 2 件のうち 1 件が存在しない状態でスキャンが実行されたとき
- **THEN** 存在しないディレクトリは警告ログとともにスキップされ、存在するディレクトリの動画のみが登録されて正常終了すること

#### Scenario: ルート間で重複する動画ファイルの単一登録

- **WHEN** `VIDEO_DIRS` の複数要素が同一の物理ファイルを含む（一方が他方の親、または同一パスの重複指定）状態でスキャンが実行されたとき
- **THEN** 同一の物理ファイルは動画として 1 件のみ登録されること

## ADDED Requirements

### Requirement: 動画ディレクトリ設定の必須化と区切り規則

システムは、動画ディレクトリの指定に `VIDEO_DIRS` のみを使用し、旧 `VIDEO_DIR` を参照してはならない（SHALL NOT）。`VIDEO_DIRS` は `;` で区切り、各要素の前後の空白と空要素を無視しなければならない（SHALL）。有効な要素が 1 件も得られない場合（未設定・空文字・空白のみ・`;` のみ）、またはフォルダ名を持たないパス（`D:\` や `/`）が含まれる場合、スキャン要求はエラーとして設定例（例: `VIDEO_DIRS=D:\Anime;F:\Movie`）を含む明確なメッセージを返さなければならない（SHALL）。旧 `VIDEO_DIR` のみが設定されている場合、廃止の旨と `VIDEO_DIRS` への移行案内をメッセージに含めなければならない（SHALL）。

#### Scenario: VIDEO_DIRS 未設定時の明確なエラー

- **WHEN** `VIDEO_DIRS` が未設定または空白のみの状態でスキャンが要求されたとき
- **THEN** 0 件成功として扱われず、設定例を含む `VIDEO_DIRS` の設定が必要である旨のエラーが返ること

#### Scenario: 旧 VIDEO_DIR のみ設定された場合

- **WHEN** `VIDEO_DIR` のみが設定され `VIDEO_DIRS` が未設定の状態でスキャンが要求されたとき
- **THEN** `VIDEO_DIR` は参照されず、旧変数が廃止された旨と `VIDEO_DIRS` への移行案内メッセージを伴うエラーとなること

#### Scenario: 空要素と余白の無視

- **WHEN** `VIDEO_DIRS` が `" D:\A ;; D:\B ;"` のように空要素・余白を含むとき
- **THEN** `D:\A` と `D:\B` の 2 件のみが走査対象として扱われること

#### Scenario: ドライブ直下の拒否

- **WHEN** `VIDEO_DIRS` に `D:\`（ドライブ直下）または `/` が含まれる状態でスキャンが要求されたとき
- **THEN** 走査は行われず、フォルダ名を持たないパスは指定できない旨のエラーが返ること

### Requirement: ルートフォルダ名とサブフォルダ名のタグ自動付与

システムは、動画が属する各ルートフォルダの名前（最終パス要素）と、ルートからの相対サブフォルダ名を、動画に自動的にタグとして作成・付与しなければならない（SHALL）。異なるルートで同名（大文字小文字を区別しない）のフォルダは 1 つのタグに統合しなければならない（SHALL）。また、動画が複数のルートに包含される（入れ子ルート）場合、所属するすべてのルート名および相対サブフォルダ名のタグを付与しなければならない（SHALL）。既存動画の再スキャン時も、不足しているタグがあれば安全に追加付与しなければならない（SHALL）。

#### Scenario: ルート名タグの付与

- **WHEN** `VIDEO_DIRS=D:\Anime;F:\Movie` で `D:\Anime\S1\ep1.mp4` が走査されたとき
- **THEN** 当該動画にタグ `Anime` と `S1` が付与されること

#### Scenario: 同名ルートのタグ統合

- **WHEN** 異なる親を持つ `D:\x\Clips` と `F:\y\clips` が `VIDEO_DIRS` に含まれるとき
- **THEN** 両ルート配下の動画に同一の 1 つのタグ `Clips`（既存タグがあればそれ）が付与され、タグが重複作成されないこと

#### Scenario: 入れ子ルートでの全ルートタグ付与

- **WHEN** `VIDEO_DIRS=D:\Anime;D:\Anime\Special` のように包含関係のルートが指定され `D:\Anime\Special\ova.mp4` が走査されたとき
- **THEN** 指定順序に関わらず、タグ `Anime` および `Special` の双方が付与されること

#### Scenario: 既存動画へのルート名タグの追記

- **WHEN** 既に DB に登録済みの動画（旧仕様等でルート名タグ未付与）に対して再スキャンが実行されたとき
- **THEN** 動画レコードの重複登録は行われず、現在のルート名タグが不足している場合にのみタグの紐付けが追加されること

### Requirement: ファイルパス正規化と重複登録防止

システムは、スキャン対象ファイルのパスを正規化（末尾区切り除去、絶対パス化、Windows 環境における大文字小文字差異の同一視）してデータベースの `FilePath` と照合しなければならない（SHALL）。大文字小文字の表記揺れやパス指定方法の違いによって同一物理ファイルが別レコードとして多重登録されてはならない（SHALL NOT）。

#### Scenario: 大文字小文字表記揺れの再スキャン

- **WHEN** `d:\videos\a.mp4` として登録済みの環境で、`D:\VIDEOS` を指定して再スキャンが実行されたとき
- **THEN** 新規レコードとして追加されず、既存の動画レコードとして認識されること

### Requirement: スキャン失敗時の UI エラー詳細通知

フロントエンド（Web UI）は、スキャン同期 API の呼び出しが失敗した際、固定メッセージのみを表示するのではなく、API が返却したエラー詳細内容および設定例をトースト通知に表示し、利用者が画面上で原因と対処法を確認できるようにしなければならない（SHALL）。

#### Scenario: 設定不備トーストの表示

- **WHEN** `VIDEO_DIRS` 未設定等の理由によりスキャン API が 500 エラーを返却したとき
- **THEN** トースト通知に「スキャン同期に失敗しました。」とともに、API から受信した設定例を含む詳細エラーメッセージが表示されること
