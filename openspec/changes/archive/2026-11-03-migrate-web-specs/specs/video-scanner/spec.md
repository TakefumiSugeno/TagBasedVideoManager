# video-scanner Specification

## Purpose

ホストOS上の動画ディレクトリを再帰的に走査して新規動画を即座にデータベースへ登録し、バックグラウンドの非同期パイプライン（FFmpeg/ffprobe）により再生時間取得とサムネイル生成を安全・高速に実行する機能を提供する。

## ADDED Requirements

### Requirement: ディレクトリ再帰走査とリパースポイント追跡

システムは、指定された動画ディレクトリ（`VIDEO_DIR`）配下を再帰的に走査し、対応拡張子（`.mp4`）の動画ファイルを検出しなければならない（SHALL）。また、シンボリックリンクやジャンクションが存在する場合、実体パスを解決して走査を継続しなければならない（SHALL）。対象ディレクトリが存在しない場合はエラーとせず 0 件として安全に終了しなければならない（SHALL）。

#### Scenario: 通常ファイルおよびシンボリックリンク配下の動画検出

- **WHEN** スキャン処理が実行されたとき
- **THEN** ルートフォルダおよびシンボリックリンク先のすべての `.mp4` ファイルが検出されること

#### Scenario: 存在しないディレクトリの安全走査

- **WHEN** `VIDEO_DIR` が存在しない状態でスキャンが実行されたとき
- **THEN** 例外終了せず、走査結果 0 件（`Ok 0`）として安全に処理を完了すること

### Requirement: 新規動画の即時DB登録と非同期キュー投入

システムは、新規検出された動画ファイルについて、ファイル情報（ファイル名、相対パス、ファイルサイズ）のみで即座にデータベースへ登録（Duration=0、ThumbnailPath=None）し、メディア処理キューへ非同期投入しなければならない（SHALL）。

#### Scenario: 新規動画の即時DB保存とUIレスポンス

- **WHEN** 新規の動画ファイルがスキャンされたとき
- **THEN** 重いメディア処理を待たずに即座に動画レコードがDBに保存され、一覧画面へ反映可能となること

### Requirement: 既存動画の未処理検出と無限ループ防止

システムは、既存動画の再スキャン時、サムネイルまたは再生時間が未取得の動画をキューへ再投入しなければならない（SHALL）。ただし、再生時間が取得済み（Duration > 0）でサムネイルのみが存在しないレコードは、処理失敗済みとみなして再投入から除外し、無限ループを防止しなければならない（SHALL）。また、ffprobeによるメタデータ解析に失敗した動画は既定値（120秒）等で救済してDB更新し、再スキャン時の無限滞留を防止しなければならない（SHALL）。

#### Scenario: 処理失敗レコードの再投入スキップ

- **WHEN** Duration > 0 かつ ThumbnailPath が null である既存動画が存在するとき
- **THEN** 再スキャン実行時に当該動画はメディア処理キューへ再投入されないこと

#### Scenario: メタデータ解析失敗動画の救済フォールバック

- **WHEN** 破損動画等のため ffprobe の再生時間解析が失敗したとき
- **THEN** 既定再生時間（120秒）でメタデータが登録され、以降の無限再試行から除外されること

### Requirement: 2段階シークによるサムネイル生成

システムは、FFmpegによるサムネイル生成時、まず動画の中間地点をシーク位置として入力ファイル指定前に `-ss` を配置する「高速シーク」を試行し、失敗時のみ入力ファイル指定後に `-ss` を配置する「安全シーク」へフォールバックしなければならない（SHALL）。

#### Scenario: 高速シーク成功

- **WHEN** 高速シーク（コンテナシーク）によってサムネイル画像が出力されたとき
- **THEN** 安全シーク（デコードシーク）を実行することなく処理を完了すること

#### Scenario: 高速シーク失敗時の自動フォールバック

- **WHEN** 高速シークによる画像出力が失敗したとき
- **THEN** 自動的に安全シークが実行され、画像が生成されること

### Requirement: メディア処理プロセスの同時実行制御とデッドロック防止

システムは、FFmpegプロセスの同時実行数をセマフォにより1件に制限し、軽量なffprobeプロセスは並行実行しなければならない（SHALL）。また、プロセス実行時は標準出力と標準エラー出力を並行タスクで非同期に読み取り、バッファ溢れによるデッドロックを防止しなければならない（SHALL）。

#### Scenario: FFmpegの逐次実行

- **WHEN** 複数の動画が同時にメディア処理キューに滞留しているとき
- **THEN** FFmpegプロセスは同時に2つ以上起動せず、1件ずつ順次処理されること

#### Scenario: 標準エラーバッファのデッドロック防止

- **WHEN** FFmpegが大量のエラー・警告ログを標準エラー出力へ書き込んだとき
- **THEN** プロセスがハングアップすることなく正常に終了または例外ハンドリングされること

### Requirement: フォルダ名からのフラットタグ自動付与

システムは、動画ファイルのディレクトリ走査時、動画が配置されているフォルダパスの各親・子フォルダ名を抽出し、タグとして自動生成（重複排除、ParentId=None）して動画へ自動付与しなければならない（SHALL）。

#### Scenario: フォルダ名タグの自動紐付け

- **WHEN** `VIDEO_DIR/Touring/2026/sample.mp4` がスキャンされたとき
- **THEN** 「Touring」および「2026」というタグが自動生成され、動画へ紐付けられること

### Requirement: メディア処理の手動停止と安全中断

システムは、バックグラウンドで進行中のメディア処理を停止するAPI（`POST /api/media/stop`）を提供し、処理キューをクリアした上で実行中の外部プロセスを安全に強制終了（Kill）し、キューの永久停止を防がなければならない（SHALL）。

#### Scenario: メディア処理の中断実行

- **WHEN** クライアントから `POST /api/media/stop` が呼び出されたとき
- **THEN** キュー内の待機タスクが全破棄され、実行中のFFmpeg/ffprobeプロセスが直ちに終了すること
