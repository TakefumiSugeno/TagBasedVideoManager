# viewing-analytics Specification

## Purpose

動画の再生履歴に基づく再生数ランキング、登録タグと文字種境界を組み合わせたハイブリッドキーワード抽出によるおすすめ動画レコメンド、およびシステムの例外エラーログモニタリング・死活監視機能を提供する。

## ADDED Requirements

### Requirement: 再生回数ランキングの集計と取得

システムは、再生回数（`AccessCount`）が多い順に上位100件の動画一覧を取得するAPI（`GET /api/analysis/ranking`）を提供し、分析ダッシュボード上で順位および再生回数を一覧表示しなければならない（SHALL）。

#### Scenario: 再生数ランキングの表示

- **WHEN** ユーザーが分析ダッシュボードの「再生数ランキング」タブを開いたとき
- **THEN** 再生回数の多い順にソートされた動画リスト（最大100件）が表示されること

#### Scenario: 再生履歴が存在しない初期状態 (Zero-State)

- **WHEN** 全動画の再生回数が 0 回である状態でランキング画面を開いたとき
- **THEN** ランキング領域に「再生履歴のある動画がまだありません」という案内メッセージが表示されること

### Requirement: ハイブリッド嗜好キーワード抽出とおすすめ動画レコメンド

システムは、再生回数1回以上の動画ファイル名から、「登録タグ辞書優先マッチング」と「文字種境界（漢字・カタカナ・英数字）分割」を組み合わせたハイブリッド方式により頻出上位5件の嗜好キーワードを抽出し、そのキーワードを含む動画（未再生動画優先）を上位20件レコメンド（`GET /api/analysis/recommendations`）しなければならない（SHALL）。

#### Scenario: 嗜好キーワードとおすすめ動画の自動提示

- **WHEN** ユーザーが分析ダッシュボードの「あなたへのおすすめ」を開いたとき
- **THEN** 抽出された嗜好キーワードバッジと、それらに合致する未再生動画を中心としたおすすめ動画20件が表示されること

#### Scenario: 再生履歴が存在しない初期状態 (Zero-State)

- **WHEN** ライブラリ内に一度も再生された動画が存在しない（再生回数がすべて 0）とき
- **THEN** おすすめキーワードおよび動画リストは空配列として安全に返却され、UI上に初期メッセージが表示されること

### Requirement: 例外エラーログの履歴取得と自動クリア

システムは、バックグラウンド処理等で発生した例外ログ（メッセージ、スタックトレース、発生日時）を取得するAPI（`GET /api/analysis/logs`、最大100件）を提供しなければならない（SHALL）。また、データベース肥大化を防止するため、アプリケーション起動時に `ErrorLogs` テーブルを自動的に全件削除（クリア）しなければならない（SHALL）。

#### Scenario: エラーログの確認

- **WHEN** 管理者が分析ダッシュボードの「エラーログ」画面を開いたとき
- **THEN** システムで発生した直近の例外エラー一覧とスタックトレースが時系列順に確認できること

#### Scenario: エラーログが存在しない初期状態 (Zero-State)

- **WHEN** システムで一度も例外エラーが発生していない（または起動直後でクリア済み）とき
- **THEN** エラーログ一覧に「現在記録されているエラーログはありません」というメッセージが表示されること

#### Scenario: アプリ起動時のログクリーンアップ

- **WHEN** アプリケーション（バックエンド）が再起動されたとき
- **THEN** 過去のエラーログレコードが自動クリアされ、新規稼働セッションのログのみが記録対象となること

### Requirement: システム死活監視とヘルスチェック

システムは、デスクトップコンパニオン等の外部ツールがサーバーの稼働状態を確認するためのヘルスチェックエンドポイント（`GET /api/ping`）を提供し、正常稼働時にプレーンテキスト「pong」を即座に応答しなければならない（SHALL）。

#### Scenario: ヘルスチェック疎通確認

- **WHEN** クライアントから `GET /api/ping` が送信されたとき
- **THEN** HTTP 200 と共にプレーンテキスト「pong」が返却されること
