# tag-management Specification

## Purpose

自己参照型階層タグによる柔軟な動画分類、動的件数バッジ集計、詳細条件に基づく自動タグ付けルールエンジンと既存動画への遡及適用、および設定情報の一括インポート・エクスポート機能を提供する。

## ADDED Requirements

### Requirement: 自己参照階層型タグの管理と動的件数集計

システムは、親子関係（`ParentId`）を持つタグの作成、名称変更、親タグ変更、削除機能を提供しなければならない（SHALL）。また、各タグ一覧取得時（`GET /api/tags`）、当該タグに紐づく動画件数を再帰CTE等により自動集計した `VideoCount` を付与して返却しなければならない（SHALL）。親タグが削除された場合、配下の子タグは削除されず親タグIDが null に解除（孤立化防止・保持）されなければならない（SHALL）。

#### Scenario: 親タグの更新とツリー構造の変更

- **WHEN** クライアントから `PATCH /api/tags/{id}` で新たな `parentId` が送信されたとき
- **THEN** タグの親IDが更新され、階層構造が再構成されること

#### Scenario: 動的件数バッジの取得

- **WHEN** `GET /api/tags` が要求されたとき
- **THEN** 各タグオブジェクトに最新の紐付け動画件数（`videoCount`）が含まれて返却されること

#### Scenario: 親タグ削除時における子タグの親解除 (SET NULL)

- **WHEN** 子タグを持つ親タグに対して `DELETE /api/tags/{id}` が実行されたとき
- **THEN** 親タグのみが削除され、配下の子タグの `ParentId` は null に更新されてルートタグとして保持されること

### Requirement: タグ階層の循環参照防止バリデーション

システムは、タグの親ID変更時（`PATCH /api/tags/{id}`）、自分自身を親に指定する操作や、自身の子孫タグを親に指定して循環参照（閉路）を形成する不正な更新要求を拒否しなければならない（SHALL）。

#### Scenario: 自分自身を親に指定した不正更新の拒否

- **WHEN** クライアントがタグID "t_1" に対して親IDとして "t_1" を指定して更新を試みたとき
- **THEN** サーバーは不正リクエストとして更新を拒否し、エラーを返却すること

### Requirement: 単一動画へのタグ紐付けおよび解除

システムは、動画へのタグ追加（`POST /api/videos/{id}/tags`）およびタグ解除（`DELETE /api/videos/{id}/tags`）を提供しなければならない（SHALL）。タグ解除時はリクエストボディに JSON 形式で `{ "tagId": "..." }` を受け付け、`200 OK` を返却しなければならない（SHALL）。

#### Scenario: 単一動画からのタグ解除

- **WHEN** クライアントが `DELETE /api/videos/{id}/tags` に対し body `{ "tagId": "t_1" }` を送信したとき
- **THEN** VideoTags テーブルから紐付けが削除され、HTTP 200 と共に `{ videoId, tagId }` が返却されること

### Requirement: 複数動画に対するタグの一括追加および一括削除

システムは、複数選択された動画に対して一括でタグを追加する `POST /api/videos/batch/tags/add`、および一括削除する `POST /api/videos/batch/tags/remove` を提供しなければならない（SHALL）。

#### Scenario: 選択動画への一括タグ付与

- **WHEN** 複数の動画IDと1つのタグIDを指定して一括追加APIが呼び出されたとき
- **THEN** 指定されたすべての動画に当該タグが一括で紐付けられること

### Requirement: 自動タグ付けルールと既存動画への遡及適用

システムは、パターン（前方一致・後方一致・部分一致・正規表現）、対象フィールド（ファイル名・ファイルパス・フォルダ名）、およびファイルサイズ範囲（MinSize/MaxSize [MB]）を指定可能な自動ルールを提供しなければならない（SHALL）。新規ルール作成時（`POST /api/rules`）および更新時（`PUT /api/rules/{id}`）は、登録済みの全既存動画に対して非同期にルールを遡及適用しなければならない（SHALL）。

#### Scenario: ルール作成時の遡及適用

- **WHEN** 「タイトルに『Camp』を含む場合、タグ『アウトドア』を付与」というルールを新規作成したとき
- **THEN** ルールがDBに保存されると同時に、過去にスキャン済みの該当動画にも自動でタグが付与されること

### Requirement: タグ階層および自動ルールのインポート・エクスポート

システムは、タグ階層構造（TSV/JSON）および自動タグ付けルール（TSV/JSON）の一括インポートAPI（`POST /api/tags/import`, `POST /api/rules/import`）を提供し、既存設定と同一形式でエクスポート可能にしなければならない（SHALL）。

#### Scenario: TSV形式によるタグ階層の一括インポート

- **WHEN** タグ名、カラーコード、親タグIDを含むTSVテキストがインポートAPIへ送信されたとき
- **THEN** トランザクション内で全タグが一括登録・更新されること
