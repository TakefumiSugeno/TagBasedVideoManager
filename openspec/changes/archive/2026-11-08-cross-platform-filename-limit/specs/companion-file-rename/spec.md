# Spec Delta: companion-file-rename

## MODIFIED Requirements

### Requirement: マウント不可（パス長超過）ファイルの自動抽出と起動中閾値変更

システムは、指定されたルートディレクトリ配下の動画ファイル（.mp4等）を再帰的にスキャンし、Windows パス長制限（フルパス文字数 ≧ 閾値、初期値: 240文字）または Linux ファイル名制限（ファイル名単体の UTF-8 バイト数 ≧ 閾値、初期値: 240バイト）のいずれか一方にでも抵触するファイルを自動抽出して一覧表示しなければならない（SHALL）。また、ユーザーは起動中にUI上でこの抽出基準文字数・バイト数を一時変更できなければならないが、設定ファイルへは書き戻してはならない（SHALL NOT）。

#### Scenario: 初期値による自動抽出と起動中の一時閾値変更

- **WHEN** ユーザーが「リネーム対象抽出＆AI提案を実行」を実行したとき
- **THEN** 設定ファイルの初期値（240文字または240バイト）以上のファイルが抽出され、UI上で数値を変更した場合は設定ファイルを更新することなく即座に対象ファイル一覧が動的に絞り込まれること

#### Scenario: Windows長パスファイルとLinux長ファイル名ファイルの包括抽出

- **WHEN** 指定フォルダ内にフルパス105文字だがファイル名UTF-8バイト数270Bのファイル、およびフルパス250文字でファイル名UTF-8バイト数90Bのファイルが存在し、スキャンを実行した時
- **THEN** 両方のファイルが漏れなく抽出結果一覧に含まれる

#### Scenario: 両方の基準を満たす安全なファイルの除外

- **WHEN** フルパス120文字かつファイル名UTF-8バイト数150Bの安全な動画ファイルが存在し、スキャンを実行した時
- **THEN** そのファイルは抽出結果一覧に含まれない

### Requirement: OpenRouter Freeモデルによる新ファイル名および問題発生時AIコメントの提案

システムは、抽出されたファイル情報および選択された命名規則プロンプト（Web検索結果を含む）をOpenRouterのモデルに送信し、文字数上限および Linux の UTF-8 バイト数上限（拡張子を含め UTF-8 で 240 バイト以内、かつフルパス 240 文字以内）を満たす新ファイル名候補を取得しなければならない（SHALL）。また、正常時・例外時を問わず、命名の意図・根拠・短縮内容（またはWeb検索結果の反映内容）を説明する「AIコメント」を必ず生成・保持し、常時表示しなければならない（SHALL）。

#### Scenario: 風変わりなファイル名に対するAIコメント表示

- **WHEN** 元のファイル名がランダムな英数字列等で命名規則に完全に従うことが困難なファイルに対しAI提案を生成したとき
- **THEN** 正常に命名できたファイルも含め、補完・例外理由や短縮根拠を説明するAIコメントが生成され、常時表示されること

#### Scenario: 通常短縮時およびWeb検索補完時のAIコメント常時表示

- **WHEN** ユーザーが抽出されたファイルに対してAI提案を実行したとき
- **THEN** 正常に命名できたファイルも含め、すべての提案ファイルに対して命名根拠・短縮理由を説明するAIコメントが生成され、常時表示されること

#### Scenario: UTF-8バイト数とフルパス文字数の両立短縮プロンプト送信

- **WHEN** 抽出された候補ファイル群に対してAI提案を開始した時
- **THEN** システムはプロンプトに「新ファイル名は拡張子を含めてUTF-8で240バイト以内とし、変更後のフルパスが240文字以内に収まるようにすること」を指示に含めてOpenRouterへリクエストを送信する

#### Scenario: AI提案成功時の両制約遵守とAIコメント生成

- **WHEN** OpenRouterから正常な新ファイル名候補と理由が返却された時
- **THEN** 各候補の新ファイル名が設定され、短縮意図を説明するAIコメントが保持・表示される

### Requirement: Before / After 対比プレビュー表示（上下並び・左右並び切り替え）

システムは、変更前（Before）と変更後（After）、およびAIコメントを対比表示するUIを提供しなければならない（SHALL）。各ファイル候補カードにおいて、「旧ファイル名 (BEFORE)」「新ファイル名 (AFTER)」「AIコメント (AI COMMENT)」の3行を常時固定表示し、文字数に加えてファイル名単体の UTF-8 バイト数を常時併記しなければならない（SHALL）。上下並び表示において、BEFORE行とAFTER行の左側ラベル領域の幅をコンパクトに固定（195px等）し、ファイル名テキストおよび入力欄の開始X座標を左に寄せて垂直に完全に一致させなければならない（SHALL）。また、AFTER においてフルパス文字数が閾値未満かつファイル名 UTF-8 バイト数が 240 バイト以内である場合に「✓ [安全]」バッジを表示し、241〜255 バイトの場合は注意バッジ（黄色）、256 バイト以上またはフルパスが閾値以上の場合は該当する危険警告バッジ（赤色）を表示しなければならない（SHALL）。

#### Scenario: 上下並びでの素早い目視確認と手動修正

- **WHEN** 上下並び表示モードを選択したとき
- **THEN** 各ファイルのBefore行とAfter行、および常時表示されるAIコメント行が最小限の高さで隣接して描画され、ユーザーが新ファイル名を直接テキストボックスで手動微調整できること

#### Scenario: 3行常時表示による素早い目視確認と手動修正

- **WHEN** 候補一覧を表示したとき
- **THEN** 各候補カード内に「BEFORE行」「AFTER行」「AI COMMENT行」の3行が常に描画され、未提案状態ではプレースホルダー、提案完了後は新ファイル名とAIコメントが整然と表示されること

#### Scenario: 両制約クリア時の安全バッジ表示

- **WHEN** AFTERの新ファイル名がフルパス180文字かつファイル名UTF-8バイト数160Bである時
- **THEN** AFTER行に「AFTER (180字 / 160B [安全])」バッジが緑色（安全色）で表示される

#### Scenario: 手動編集によるLinuxバイト数超過時の即時警告表示

- **WHEN** ユーザーがAFTERの新ファイル名を手動編集し、ファイル名UTF-8バイト数が256バイト以上となった時
- **THEN** AFTER行のバッジが「AFTER (〇〇字 / 〇〇B [Linux危険])」の赤色警告バッジに即座に切り替わる

### Requirement: 重複回避と安全な物理リネーム実行

システムは、ユーザーが確定した新ファイル名へのリネームを実行する際、移動先ファイル名の重複チェックを行い、同名ファイルが既に存在する場合は末尾に連番サフィックス（`_1.mp4`等）を付与して一意なファイル名を導出しなければならない（SHALL）。連番付与時においても、最終ファイル名が UTF-8 で 240 バイト以内およびフルパス 240 文字以内を維持するよう必要に応じてベース名をトリミングし、上限を再超過させてはならない（SHALL NOT）。エラー時は安全にロールバックして結果レポートを表示しなければならない（SHALL）。

#### Scenario: 一括リネームの安全な実行

- **WHEN** ユーザーがチェックしたファイルに対して一括リネームを実行したとき
- **THEN** ホストOS上で物理ファイルがリネームされ、成功・失敗（および失敗理由）が画面上に明確にレポートされること

#### Scenario: 同名衝突時の連番サフィックス付加とバイト数再超過防止

- **WHEN** リネーム先のディレクトリに同名ファイルが既に存在し、連番サフィックスが付加された時
- **THEN** サフィックス付加後のファイル名が UTF-8 で 240 バイト以内およびフルパス 240 文字以内に維持された状態で安全に移動が行われること

## ADDED Requirements

### Requirement: 制約違反理由の可視化と表示フィルタ

システムは、抽出された各ファイルに対し、どの制約に違反しているか（Windows パス長超過、Linux ファイル名超過、または両方超過）を判定し、候補カードの BEFORE 行に専用バッジ（`[🪟 Windows: パス長超過]`、`[🐧 Linux: ファイル名超過]`、`[⚠️ 両方超過]`）を表示しなければならない（SHALL）。また、ツールバーに表示フィルタを提供し、「すべて」「Linuxファイル名超過のみ」「Windowsパス長超過のみ」「両方超過」の条件でリストを絞り込み表示できなければならない（SHALL）。さらに、抽出候補が 0 件の時やフィルタ適用で該当ファイルが 0 件となった場合、リスト領域に全件安全である旨を示す Empty State メッセージを表示しなければならない（SHALL）。

#### Scenario: 制約種別バッジの正確な表示

- **WHEN** フルパス100文字・ファイル名UTF-8バイト数270Bのファイルが表示された時
- **THEN** BEFORE行に「🐧 [Linux: ファイル名超過 (270B / 上限255B)]」の赤色バッジが表示される

#### Scenario: 表示フィルタによるLinux超過ファイルの絞り込み

- **WHEN** ユーザーが表示フィルタで「Linuxファイル名超過のみ」を選択した時
- **THEN** ファイル名UTF-8バイト数が閾値（240バイト）以上のファイルのみがリストに表示され、Windowsパス長のみが超過しているファイルは一時的に非表示となる

#### Scenario: 表示フィルタを「すべて」に戻した際の全件再表示

- **WHEN** 表示フィルタを「すべて」に切り替えた時
- **THEN** 抽出されたすべての候補ファイルが再び一覧に表示される

#### Scenario: 候補0件時のEmpty State案内表示

- **WHEN** 走査対象ディレクトリ内に制限超過ファイルが1件も存在しない、またはフィルタ条件に合致する候補が0件である時
- **THEN** リスト領域に「対象ファイルはありません。すべてのファイルが安全です」の安心メッセージが表示される
