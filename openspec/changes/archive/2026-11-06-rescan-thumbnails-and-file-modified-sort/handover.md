## 1. 変更サマリ

本変更は、Issue #14 および Issue #15 を包括的に解決するための改修である。

1. **サムネイル未作成動画の再処理投入と出力先自動生成 (Issue #14)**:
   従来は `Duration > 0` かつ `ThumbnailPath = None` の動画が処理失敗と判定されて再スキャン時にスキップされていたが、`ThumbnailPath = None` の場合は無条件で再処理キューへ投入するように修正。また、出力先ディレクトリ（`THUMBNAIL_DIR`）を起動時・スキャン時・生成前の3重で自動生成するように強化。
2. **ファイル更新日時の記録と初期ソートへの採用 (Issue #15)**:
   ホストOSファイルシステムの最終更新日時（`LastWriteTimeUtc`）を `FileModifiedAt` として取得・保存し、既存データにはスキャン時の自動バックフィルを実装。Web UI の並び替えドロップダウンおよびモバイル設定シートに「ファイル更新日」（初期値）と「TBVM登録日」を追加。

### 原因と対応

- **原因**:
  - Issue #14: 無限ループ防止仕様の誤適用により、`THUMBNAIL_DIR` 不在等でサムネイル生成に失敗した 1,068 件の動画が永久に再処理されないゾンビ状態となっていた。
  - Issue #15: ホストOS側で追加・更新された動画を最新順に確認する手段がなく、システム登録日（`CreatedAt`）しか保持していなかった。
- **対応**:
  1. `Scanner.fs` の再処理判定を `ThumbnailPath = None` または実ファイル不在時に無条件でキュー投入するように改修。
  2. `Media.fs` に親ディレクトリ自動作成および null ガードを追加。
  3. `Domain.fs`, `Db.fs` に `FileModifiedAt` を追加し、起動時の `ALTER TABLE Videos ADD COLUMN FileModifiedAt TEXT` 自動マイグレーションと `updateVideoFileModifiedAt` によるバックフィルを実装。
  4. Web UI（`app.js`, `index.html`）の並び替え初期値を「ファイル更新日」に変更し、選択肢順序を整理。

## 4. 将来の改善・リファクタ候補

- **動画ファイル削除時の物理サムネイルのクリーンアップ**:
  動画ファイルが削除された際、生成済みサムネイル画像（`.jpg`）が孤立して残るため、定期的な孤立サムネイル削除ガベージコレクションの導入を検討。
- **大量スキャン時のバックフィル一括バルク更新**:
  現在は差分のある動画のみ個別 UPDATE しているが、万単位の動画を初回到来スキャンする場合はバルクトランザクション化による更なる高速化が可能。

---

## 5. 運用上の注意事項

- **データベースマイグレーション**:
  起動時に `ALTER TABLE Videos ADD COLUMN FileModifiedAt TEXT` が自動実行されるため、手動のマイグレーション作業は不要。
- **ロールバック手順**:
  万が一ロールバックが必要な場合でも、SQLite の `FileModifiedAt` カラムは旧バージョンで無視されるため、旧バイナリ（コンテナイメージ）に差し戻すだけでデータ損失なく安全に復旧可能。
