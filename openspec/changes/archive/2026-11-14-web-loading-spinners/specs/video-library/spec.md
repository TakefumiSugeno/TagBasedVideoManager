# Spec Delta: video-library

## ADDED Requirements

### Requirement: 動画一覧の非同期ロード中およびスキャン中におけるスピナー表示と Zero-State 誤表示防止

フロントエンド（Web UI）は、動画一覧の非同期データ取得（初回ロード時、再読み込み時）を実行中、コンテンツ領域の中央にスピナーおよび「動画を読み込み中...」のテキストを表示しなければならない（SHALL）。データ取得実行中（`isLoadingVideos === true`）またはディレクトリ同期実行中（`isScanning === true`）の間は、動画件数が 0 件であっても「動画が見つかりませんでした」という Zero-State 画面を表示してはならない（SHALL NOT）。データ取得および同期が完了した時点で取得件数が 0 件である場合のみ Zero-State 画面を表示しなければならない（SHALL）。また、Zero-State 画面にはユーザーが即座に操作を再開できるよう、「ディレクトリ同期を実行する」ボタンおよび（検索クエリ入力時）「検索条件をクリアする」ボタンを提供しなければならない（SHALL）。

#### Scenario: 初回ロード中のスピナー表示と Zero-State 抑止

- **WHEN** ユーザーが Web UI にアクセスし、動画一覧データ取得リクエストが実行中であるとき
- **THEN** 「動画が見つかりませんでした」が表示されず、画面中央にスピナーと「動画を読み込み中...」が表示されること

#### Scenario: ディレクトリ同期実行中（isScanning）の Zero-State 抑止

- **WHEN** 初回ロード等で動画が 0 件であり、バックグラウンド同期（`isScanning === true`）が実行中であるとき
- **THEN** 「動画が見つかりませんでした」が表示されず、同期中インジケータが表示されること

#### Scenario: データ0件時の Zero-State 正常表示と回復導線

- **WHEN** 動画一覧データ取得および同期が完了し、動画件数が 0 件であるとき
- **THEN** スピナーが非表示となり、「動画が見つかりませんでした」とともに「ディレクトリ同期を実行する」ボタンが表示されること

#### Scenario: 検索結果0件時の検索クリアボタン表示

- **WHEN** 検索キーワードを入力して検索が完了し、該当動画が 0 件であったとき
- **THEN** 「動画が見つかりませんでした」とともに「検索条件をクリアする」ボタンが表示され、クリックで検索バーがリセットされて全件一覧が再取得されること

### Requirement: 検索・絞り込み・ページ切り替え時の一覧オーバーレイ・スピナー表示と多重クリック抑止

フロントエンド（Web UI）は、既存の動画一覧が表示されている状態で、検索キーワード入力、タグ絞り込み、お気に入り切り替え、スマートフォルダ切り替え、ソート順変更、またはページ切り替えによる非同期データ再取得が発生した場合、既存の一覧表示を維持したまま一覧領域全体に半透明オーバーレイ（クリック遮断付き）および中央スピナーを表示しなければならない（SHALL）。また、検索バー内のアイコンを回転スピナー表示に切り替えなければならない（SHALL）。オーバーレイ表示中は背後の動画カードやボタンのクリック操作を遮断（`pointer-events-auto`）しなければならない（SHALL）。非同期通信が完了したとき、オーバーレイとスピナーを解除し、最新の動画一覧を表示しなければならない（SHALL）。

#### Scenario: 検索実行時の半透明オーバーレイとスピナー表示

- **WHEN** 動画一覧が表示されている状態で、ユーザーが検索キーワードを入力して非同期通信が開始されたとき
- **THEN** 既存の一覧の上に半透明オーバーレイと中央スピナーが表示され、検索バーのアイコンがスピナー表示となること

#### Scenario: オーバーレイ表示中の背後操作の抑止

- **WHEN** 一覧領域に半透明オーバーレイが表示されているとき
- **THEN** 背後の動画カードやボタンをクリックしても反応せず、多重リクエストや予期せぬ画面遷移が発生しないこと

#### Scenario: 検索完了時のオーバーレイ解除と結果描画

- **WHEN** 検索クエリの非同期通信が完了したとき
- **THEN** 半透明オーバーレイとスピナーが解除され、検索結果の動画一覧が描画されること

#### Scenario: タグ絞り込み時のオーバーレイ表示

- **WHEN** ユーザーがタグをクリックして一覧の絞り込み非同期通信が開始されたとき
- **THEN** 一覧領域に半透明オーバーレイとスピナーが表示され、通信完了後に絞り込み結果が表示されること

### Requirement: 連続操作時のレースコンディション抑止と最新リクエスト維持

フロントエンド（Web UI）は、検索キーワード入力やタグ切り替え等の非同期リクエストが短時間に連続して発生した場合、各リクエストに単調増加の一意なリクエストIDを付与しなければならない（SHALL）。先行リクエストの応答が遅延して後続リクエストよりも後に到着した場合、その古い応答を破棄して最新リクエストの結果のみを画面に反映しなければならない（SHALL）。また、先行リクエストが完了・破棄された時点で後続リクエストがまだ通信中である場合、ローディング状態（スピナーおよびオーバーレイ）を解除してはならず（SHALL NOT）、最新リクエストの完了時までローディング表示を継続維持しなければならない（SHALL）。

#### Scenario: 連続検索時の遅延古いレスポンス破棄

- **WHEN** ユーザーが「A」と入力した直後に「AB」と入力し、「A」の応答が「AB」の応答より遅れて到着したとき
- **THEN** 「A」の検索結果は破棄され、画面には「AB」の検索結果のみが表示されること

#### Scenario: 連続操作時のローディング状態の途切れなき継続

- **WHEN** リクエスト1の通信中にリクエスト2が送信され、リクエスト1の処理が先に完了したとき
- **THEN** リクエスト1完了時点でスピナーやオーバーレイが消去されず、リクエスト2が完了するまでローディング表示が途切れず継続すること

### Requirement: 動画一覧取得エラー時の Error-State 表示と再試行導線

フロントエンド（Web UI）は、動画一覧取得 API 通信が失敗（HTTP 5xx、4xx、ネットワーク切断、タイムアウト等）した場合、スピナーを安全に解除し、画面中央にエラーメッセージ、障害内容、および「再試行」ボタンを表示しなければならない（SHALL）。また、エラー発生時は詳細なログ（リクエストURL、HTTPステータス等）をブラウザコンソールに出力し、トースト通知を表示しなければならない（SHALL）。「再試行」ボタンがクリックされた場合、再度 `fetchVideos()` を実行してデータの再取得を試行しなければならない（SHALL）。

#### Scenario: 通信エラー時のエラー画面表示と再試行ボタン

- **WHEN** 動画一覧取得 API が HTTP 500 やネットワーク切断で失敗したとき
- **THEN** スピナーが解除され、「動画の取得に失敗しました」というメッセージと「再試行」ボタンが表示され、Zero-State や空画面で放置されないこと

#### Scenario: 再試行ボタン押下による再リクエスト成功

- **WHEN** エラー画面でユーザーが「再試行」ボタンをクリックしたとき
- **THEN** 再びローディングスピナーが表示され、API リクエストが再送されること
