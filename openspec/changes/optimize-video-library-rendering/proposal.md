# Proposal: optimize-video-library-rendering

- **規模レベル**: L2
- **変更種別**: fix (パフォーマンス改善)
- **関連Issue**: [#25 [機能改善]動画ライブラリのデータ表示が遅い。](https://github.com/TakefumiSugeno/TagBasedVideoManager/issues/25)

## Why

Webブラウザ上で動画ライブラリ画面を開いた際、および検索・フィルタリング操作を行った際に、描画開始までに2テンポ程度の体感遅延が発生している。

### 根本原因 (Root Cause)

1. **バックエンドの直列 N+1 クエリ**:
   `Db.getVideos` および `Db.searchVideos` において、`SELECT ... FROM Videos` で全動画を取得後、各動画に紐付くタグ情報を `Async.Sequential` により 1 件ずつ直列に SQL を発行して取得している。動画数が 100〜500 件ある場合、101〜501 回の DB 往復クエリが直列に走り、API レスポンスを著しく悪化させている（スキャン時も同様）。
2. **サムネイル画像の一斉リクエスト集中**:
   フロントエンド (`index.html`) のサムネイル `<img>` タグに `loading="lazy"` が設定されておらず、表示領域外を含む多数の画像リクエストが一斉に発生し、ネットワークとディスク I/O の競合を引き起こしている。
3. **Lucide アイコンの全 DOM 走査オーバーヘッド**:
   動画リスト更新時に `lucide.createIcons()` をページ全体スコープで毎回実行しており、不要な再描画と CPU 負荷を発生させている。

## What Changes

- **バックエンド（DBアクセス層）のタグ一括結合**:
  - `Db.getVideos` および `Db.searchVideos` において、動画一覧を取得した直後に、対象動画 ID リストに紐付くすべてのタグを **単一の一括クエリ（またはIN句を用いた結合クエリ）** で取得し、インメモリ上で各動画へマッピングする（クエリ発行回数を 1+N 回から 2 回へ削減）。
- **フロントエンドのサムネイル遅延読み込み**:
  - デスクトップ用グリッド、リスト、モバイル用グリッド、リストの各サムネイル `<img>` タグに `loading="lazy"` および `decoding="async"` 属性を付与。
- **フロントエンドのアイコン描画最適化**:
  - `lucide.createIcons()` 呼び出しの走査範囲を最適化し、不要な全画面再走査を抑止。

## Non-goals (やらないこと)

- **サーバーサイドページネーション（A-4）の導入**:
  - 2 万件規模に対応するためのサーバーサイド LIMIT/OFFSET ページネーションおよびサーバーサイドソートは、API 契約とフロントエンド状態管理の全面刷新が必要となるため、今回のスコープ外とし「フェーズ 2（スケーラビリティ拡張）」として独立した変更で実施する。
- **ファイル移動・リネーム・バインドマウント追跡（Issue #23）**:
  - 決定論的 UUID v5 によるファイル同一性判定・Reconciliation 機能は、Issue #23 専用の独立した変更で実施する。
- **UI デザイン・レイアウトの変更**:
  - カードサイズ、余白、カラーパレット等の UI/UX デザインは変更しない。

## Acceptance Criteria (受け入れ基準)

### シナリオ 1: 動画一覧 API のクエリ発行回数削減 (N+1 解消)

- **GIVEN** データベースに 100 件以上の動画が登録されている
- **WHEN** `/api/videos` が呼び出されたとき
- **THEN** タグ情報取得のための DB クエリ発行が 1 回（動画取得と合わせて計 2 回）で完了し、すべての動画に正しいタグリストが付与されて返却されること

### シナリオ 2: 検索 API におけるタグ一括取得

- **GIVEN** データベースに検索条件にヒットする複数件の動画が登録されている
- **WHEN** `/api/videos?q=...` により検索が実行されたとき
- **THEN** ヒットした動画群に対して直列 N+1 クエリが発生せず、一括クエリでタグが取得されて即座に検索結果が返却されること

### シナリオ 3: サムネイル画像の遅延ロード

- **GIVEN** 動画ライブラリ画面に多数の動画カードが描画されている
- **WHEN** 初回画面表示が行われたとき
- **THEN** 表示領域外のサムネイル画像は初期描画時に一斉フェッチされず、スクロール等で表示領域に近づいた際に遅延ロードされること

## Capabilities

### Modified Capabilities

- `video-library`: 動画一覧および検索結果取得時の高速レスポンス（N+1 クエリ廃止による一括取得）とサムネイル画像の遅延ロード要件を追加・明確化。

## Impact

- **バックエンド**:
  - `src/TagBasedVideoManager/Db.fs`: `getVideos`, `searchVideos` のタグ取得ロジック最適化（クエリ一括化）
  - `src/TagBasedVideoManager/Scanner.fs`: `syncVideoDirectories` 内での `Db.getVideos` 呼び出しも自動的に高速化
- **フロントエンド**:
  - `src/TagBasedVideoManager/wwwroot/index.html`: サムネイル画像タグへの遅延ロード属性追加
  - `src/TagBasedVideoManager/wwwroot/app.js`: アイコン生成処理の負荷軽減
- **破壊的変更**: なし（既存の API 仕様・レスポンス JSON 構造は 100% 互換維持）
