# video-library Specification

## Purpose

Webブラウザおよびモバイル端末から動画ライブラリを効率的に閲覧・検索・視聴するためのUI表示機能、HTTP 206 Rangeリクエストによるストリーミング再生、お気に入り登録、および正確な視聴アクセス履歴管理機能を提供する。

## Requirements

### Requirement: 動画一覧のグリッドおよびリスト表示

システムは、登録された動画一覧を「グリッド表示」および「リスト表示」の切り替え形式で描画しなければならない（SHALL）。また、モバイル端末（画面幅 640px 未満）においては、サムネイル重視の「2列グリッド表示」とファイル名重視の超高密度な「スリムリスト表示」をワンタップで相互に切り替えられる専用モードを提供しなければならない（SHALL）。表示形式の切り替え時においても、並び替え順序、サムネイル表示ON/OFF、再生回数リセット、お気に入り状態、複数選択、タグ付与、およびページング・追加読み込みの既存機能を一切欠落させることなく維持しなければならない（SHALL）。

#### Scenario: グリッド表示とリスト表示の切り替え

- **WHEN** ユーザーが表示形式のトグルボタンをクリックしたとき
- **THEN** 動画一覧がカード型グリッドまたは行型リスト形式へ即座に再レンダリングされること

#### Scenario: 件数ページング表示

- **WHEN** ユーザーがページング件数を指定してページ移動したとき
- **THEN** 指定件数分の動画カードのみが表示され、ページネーションコントロールが正しく更新されること

#### Scenario: 動画未登録の初期状態 (Zero-State)

- **WHEN** ライブラリ内に動画が1件も登録されていない状態でライブラリ画面を開いたとき
- **THEN** 画面が真っ白にならず、「動画が見つかりません。動画フォルダを同期してください」等の案内メッセージが表示されること

#### Scenario: モバイルでの2列グリッドとスリムリストの切り替え

- **WHEN** モバイル画面においてユーザーが表示切り替えトグルを操作した時
- **THEN** 動画一覧がサムネイル中心の2列グリッド表示と高密度なスリムリスト表示の間で即座に切り替わり、ソート順やサムネ表示状態、ページング等の既存機能が完全に維持されること。

#### Scenario: デスクトップ表示形式の維持

- **WHEN** PCデスクトップ環境で動画一覧を表示した時
- **THEN** 既存の3段階グリッドサイズ（小・中・大）および標準リスト表示が従来通り利用可能であること。

### Requirement: 動画カードの固定サイズとメタデータ常時表示

システムは、グリッド表示の各サイズ（小・中・大）においてカード全体の高さを固定化し、サムネイル、タイトル、ファイルサイズ、登録日、再生回数、タグリストを省略せず常時表示しなければならない（SHALL）。

#### Scenario: グリッド小サイズでのメタデータ常時表示

- **WHEN** グリッド表示が「小サイズ」に選択されているとき
- **THEN** すべての動画カードでサムネイル、タイトル、サイズ、登録日、再生回数、タグが欠損なく描画されること

### Requirement: タイトル文字のはみ出し時等速marquee往復スクロール

システムは、動画タイトルがカード表示幅を超過している場合、ホバー状態にかかわらず常時ゆっくりと左右等速に往復アニメーション表示（marquee）させなければならない（SHALL）。

#### Scenario: 長いタイトルの往復等速スクロール

- **WHEN** カード幅を超える長さの動画タイトルが表示されたとき
- **THEN** 文字列幅に応じた一定の速度でタイトルが左右に自動往復スクロールすること

### Requirement: HTTP Range Requests (HTTP 206) による動画ストリーミング配信

システムは、`GET /api/videos/{id}/stream` に対する Range リクエストヘッダーを解釈し、指定されたバイト範囲のストリーミングデータと HTTP 206 Partial Content レスポンスを返却しなければならない（SHALL）。対象動画の物理ファイルがストレージ上に存在しない場合は HTTP 404 Not Found を返却しなければならない（SHALL）。

#### Scenario: シーク再生時の部分コンテンツ要求

- **WHEN** クライアントから Range ヘッダーを含む動画ストリーム要求が送信されたとき
- **THEN** サーバーは HTTP 206 と共に Content-Range ヘッダーおよび要求範囲の動画バイナリを返却すること

#### Scenario: 実ファイル消失時の 404 エラー応答

- **WHEN** DBに登録されているが物理ストレージ上に実ファイルが存在しない動画のストリームが要求されたとき
- **THEN** サーバーは HTTP 404 Not Found を返却し、クライアントに動画が存在しないことを通知すること

### Requirement: 再生アクセス記録とシーク多重カウント防止

システムは、動画ストリーミング配信とは独立した専用のアクセス記録エンドポイント（`POST /api/videos/{id}/access`）を提供し、動画の再生開始時のみ再生回数をインクリメントしなければならない（SHALL）。シーク操作による部分リクエストで再生回数を増やしてはならない（SHALL NOT）。

#### Scenario: 初回再生開始時のアクセス記録

- **WHEN** クライアントが動画の再生を開始して `POST /api/videos/{id}/access` を呼び出したとき
- **THEN** 該当動画の `AccessCount` が 1 増加し、`LastAccessedAt` に現在日時が記録されること

#### Scenario: シーク操作時のカウント不変

- **WHEN** ユーザーが動画プレイヤー上で再生シークバーを複数回操作したとき
- **THEN** ストリーミング要求のみが発生し、再生回数は増加しないこと

### Requirement: 動画アクセス履歴の個別リセット

システムは、動画カードやプレイヤーから呼び出し可能な再生アクセスリセットエンドポイント（`POST /api/videos/{id}/access/clear`）を提供し、該当動画の再生回数を 0 にクリアしなければならない（SHALL）。

#### Scenario: 再生回数のクリア

- **WHEN** クライアントから `POST /api/videos/{id}/access/clear` が送信されたとき
- **THEN** 該当動画の `AccessCount` が 0 にリセットされ、`LastAccessedAt` が null となること

### Requirement: お気に入り状態の更新および一括更新

システムは、単一動画のお気に入り状態を更新する `PUT /api/videos/{id}/favorite` および、複数選択された動画を一括更新する `POST /api/videos/batch/favorite` を提供しなければならない（SHALL）。

#### Scenario: 単一動画のお気に入りトグル

- **WHEN** ユーザーが動画カードのお気に入りスターアイコンをクリックしたとき
- **THEN** サーバーへ `PUT /api/videos/{id}/favorite` が送信され、お気に入り状態が即座に反転更新されること

#### Scenario: 複数動画のお気に入り一括登録

- **WHEN** 複数動画を選択して一括お気に入り登録を実行したとき
- **THEN** 対象動画の `IsFavorite` が一括で更新されること

### Requirement: 静的ファイル配信によるサムネイル表示

システムは、動画IDに基づくサムネイル画像を `/thumbnails/{id}.jpg` の静的パスとして提供しなければならない（SHALL）。フロントエンドは動画にサムネイルが存在する場合、同静的URLを参照して画像を表示しなければならない（SHALL）。

#### Scenario: サムネイル画像の正常表示

- **WHEN** `thumbnailPath` を持つ動画が描画されるとき
- **THEN** クライアントは `/thumbnails/{id}.jpg` を読み込んでサムネイルを表示すること

#### Scenario: サムネイル未生成動画のプレースホルダー表示

- **WHEN** `thumbnailPath` が null の動画が描画されるとき
- **THEN** 代替プレースホルダー（「No Thumbnail」）が表示されること

### Requirement: モバイル常設キーワード検索欄

システムは、モバイル画面のヘッダー直下に常設のキーワード入力欄を提供し、フリーワード部分一致および `tag:xxx` 形式の DSL 検索に即時対応するインクリメンタル検索機能、ならびにワンタップ入力消去（クリア）コントロールを提供しなければならない（SHALL）。

#### Scenario: モバイル常設検索欄でのキーワード入力

- **WHEN** ユーザーが検索欄に文字列を入力した時
- **THEN** 入力文字に基づき対象動画が即座に絞り込まれ、クリアボタン（✕）が表示されること。

### Requirement: モバイル表示・ソート設定シート

システムは、モバイル画面において並び替え基準（登録日時、ファイル名、再生回数、再生時間）、昇順/降順、サムネイル表示切り替え、および読み込みモード（ページング vs 順次追加読み込み）を指先で容易に変更可能なスライド式設定シートを提供しなければならない（SHALL）。

#### Scenario: 設定シートでの並び替え条件変更

- **WHEN** ユーザーが表示設定シートを開き、並び替え基準や昇順/降順を変更した時
- **THEN** 現在の表示モード（2列グリッドまたはスリムリスト）にかかわらず、指定した順序で即座に一覧が並び替えられること。

### Requirement: モバイル全画面プレイヤーおよび連続視聴ナビゲーション

システムは、モバイル端末における動画再生時、画面余白を排除した全画面没入型プレイヤーを提供し、一覧画面に戻ることなく前後の動画へシームレスに切り替えて再生できる連続視聴ナビゲーションコントロールを提供しなければならない（SHALL）。また、端末の横画面（ランドスケープ）への回転時に自動で横全画面表示へ追従しなければならない（SHALL）。

#### Scenario: モバイルでの動画タップによる全画面再生開始

- **WHEN** モバイル一覧上で動画サムネイルまたはタイトルをタップした時
- **THEN** 画面全体を覆うプレイヤーが起動し、対象動画のストリーミング再生が即座に開始されること。

#### Scenario: 前後の動画へのシームレス移動

- **WHEN** プレイヤー表示中に「次の動画」または「前の動画」ボタンをタップした時
- **THEN** 一覧に戻ることなく、現在フィルタ・ソートされている動画順に従って対象の動画が切り替わり再生されること。

#### Scenario: ランドスケープ表示への追従

- **WHEN** モバイル端末を横向きに回転させた時
- **THEN** プレイヤーが画面アスペクト比に合わせて最大化表示されること。

### Requirement: モバイル各種子画面モーダルの最適化表示

システムは、統計・おすすめ動画、一括インポート/エクスポート、自動適用ルール管理、スマートフォルダ保存、動画へのタグ付与、および一括タグ操作の各モーダルダイアログを、モバイル画面幅（< 640px）において画面外への突き抜けや操作不能を起こすことなく閲覧・実行できるよう最適化表示しなければならない（SHALL）。

#### Scenario: モバイルでの各種管理モーダル起動と操作

- **WHEN** モバイル端末においてメニューまたは動画操作から各種子画面モーダルを開いた時
- **THEN** 画面幅に収まるスクロール可能なモーダルとして描画され、フォーム入力およびアクション実行が完結できること。

### Requirement: モバイルセーフエリアおよびダイナミックビューポート対応

システムは、モバイルブラウザのアドレスバー開閉に伴う画面高変動（Dynamic Viewport Height / 100dvh）およびノッチ・ホームインジケーター（safe-area-inset）を考慮したレイアウトを適用し、主要操作要素において最低 44x44 ピクセルのタッチ領域を確保しなければならない（SHALL）。

#### Scenario: アドレスバー開閉時のレイアウト維持

- **WHEN** モバイルブラウザでスクロールやアドレスバーの伸縮が発生した時
- **THEN** 画面最下部の一括操作バーやコンテンツが画面外に押し出されたり隠れたりせず、100dvh 内に正常に収まること。

#### Scenario: タッチターゲットのアクセシビリティ

- **WHEN** モバイル画面上でお気に入りボタン（★）や再生ボタン、閉じるボタンをタッチ操作した時
- **THEN** 44x44 ピクセル相当のタップ領域により、隣接要素の誤タップなく確実に意図した操作が反応すること。

### Requirement: モバイルヘッダーからの即時ディレクトリ同期

システムは、モバイルメイン画面のヘッダーに配置された同期ボタンからの要求を受け付け、バックグラウンドでのディレクトリ同期を実行し、実行中アニメーション表示および完了後の自動最新化を行わなければならない（SHALL）。

#### Scenario: モバイルヘッダーでの同期ボタンタップ

- **WHEN** モバイルヘッダーの同期ボタンをタップした時
- **THEN** 同期APIが呼び出され、アイコンが回転アニメーション状態となり、完了時に最新の動画一覧データへ更新されること。
