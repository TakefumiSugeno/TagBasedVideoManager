# video-library Specification

## Purpose

Webブラウザおよびモバイル端末から動画ライブラリを効率的に閲覧・検索・視聴するためのUI表示機能、HTTP 206 Rangeリクエストによるストリーミング再生、お気に入り登録、および正確な視聴アクセス履歴管理機能を提供する。

## Requirements

### Requirement: 動画一覧のグリッドおよびリスト表示

システムは、登録された動画一覧を「グリッド表示」および「リスト表示」の切り替え形式で描画しなければならない（SHALL）。また、モバイル端末（画面幅 640px 未満）においては、サムネイル重視の「2列グリッド表示」とファイル名重視の超高密度な「スリムリスト表示」をワンタップで相互に切り替えられる専用モードを提供しなければならない（SHALL）。表示形式の切り替え時においても、並び替え順序、サムネイル表示ON/OFF、再生回数リセット、お気に入り状態、複数選択、タグ付与、およびページング・追加読み込みの既存機能を一切欠落させることなく維持しなければならない（SHALL）。

#### Scenario: グリッド表示とリスト表示の切り替え

- **WHEN** ユーザーが表示形式のトグルボタンをクリックしたとき
- **THEN** 動画一覧がカード型グリッドまたは行型リスト形式へ即座に再レンダリングされること

#### Scenario: 件数ページング表示

- **WHEN** ユーザーがページング件数を指定してページ移動したとき
- **THEN** 指定件数分の動画カードのみが表示され、ページネーションコントロールが正しく更新されること

#### Scenario: 動画未登録の初期状態 (Zero-State)

- **WHEN** ライブラリ内に動画が1件も登録されていない状態でライブラリ画面を開いたとき
- **THEN** 画面が真っ白にならず、「動画が見つかりません。動画フォルダを同期してください」等の案内メッセージが表示されること

#### Scenario: モバイルでの2列グリッドとスリムリストの切り替え

- **WHEN** モバイル画面においてユーザーが表示切り替えトグルを操作した時
- **THEN** 動画一覧がサムネイル中心の2列グリッド表示と高密度なスリムリスト表示の間で即座に切り替わり、ソート順やサムネ表示状態、ページング等の既存機能が完全に維持されること。

#### Scenario: デスクトップ表示形式の維持

- **WHEN** PCデスクトップ環境で動画一覧を表示した時
- **THEN** 既存の3段階グリッドサイズ（小・中・大）および標準リスト表示が従来通り利用可能であること。

### Requirement: 動画カードの固定サイズとメタデータ常時表示

システムは、グリッド表示の各サイズ（小・中・大）においてカード全体の高さを固定化し、サムネイル、タイトル、ファイルサイズ、登録日、再生回数、タグリストを省略せず常時表示しなければならない（SHALL）。

#### Scenario: グリッド小サイズでのメタデータ常時表示

- **WHEN** グリッド表示が「小サイズ」に選択されているとき
- **THEN** すべての動画カードでサムネイル、タイトル、サイズ、登録日、再生回数、タグが欠損なく描画されること

### Requirement: タイトル文字のはみ出し時等速marquee往復スクロール

システムは、動画タイトルがカード表示幅を超過している場合、ホバー状態にかかわらず常時ゆっくりと左右等速に往復アニメーション表示（marquee）させなければならない（SHALL）。

#### Scenario: 長いタイトルの往復等速スクロール

- **WHEN** カード幅を超える長さの動画タイトルが表示されたとき
- **THEN** 文字列幅に応じた一定の速度でタイトルが左右に自動往復スクロールすること

### Requirement: HTTP Range Requests (HTTP 206) による動画ストリーミング配信

システムは、`GET /api/videos/{id}/stream` の Range ヘッダーを解釈し、指定範囲のバイナリと HTTP 206 Partial Content を返却しなければならない（SHALL）。物理ファイル不在時は HTTP 500 例外を発生させず、直ちに HTTP 404 Not Found とエラー詳細 JSON（`FILE_NOT_FOUND`）を返却しなければならない（SHALL）。また、Linux 環境等においてファイル名がカーネル制限（`NAME_MAX` 255バイト）を超過している場合、ストリーミング前にファイル名単体の UTF-8 バイト数を検査し、直ちに HTTP 422 とエラーコード `FILE_NAME_TOO_LONG` を含む JSON を返却しなければならない（SHALL）。実行中に `PathTooLongException` 等の関連例外が発生した場合も HTTP 500 クラッシュさせず（SHALL NOT）、安全に捕捉して HTTP 422 JSON を返却しなければならない（SHALL）。クライアント切断（`OperationCanceledException`）時はエラーログを記録せず静かに終了しなければならない（SHALL）。

#### Scenario: シーク再生時の部分コンテンツ要求

- **WHEN** クライアントから Range ヘッダーを含む動画ストリーム要求が送信されたとき
- **THEN** サーバーは HTTP 206 と共に Content-Range ヘッダーおよび要求範囲の動画バイナリを返却すること

#### Scenario: 実ファイル消失時の 404 エラー応答

- **WHEN** DBに登録されているが物理ストレージ上に実ファイルが存在しない動画のストリームが要求されたとき
- **THEN** サーバーは HTTP 500 エラーとならず HTTP 404 Not Found とエラーメッセージ JSON を返却し、クライアントに動画ファイルが存在しないことを通知すること

#### Scenario: Linuxファイル名長制限超過時のFail-Fast HTTP 422と専用エラーコード返却

- **WHEN** ファイル名が Linux の 255 バイト制限を超過している動画に対してストリーミング配信が要求された時
- **THEN** サーバーは 500 エラーにならず、HTTP 422 と `{"code": "FILE_NAME_TOO_LONG", "error": "ファイル名が Linux の 255 バイト制限 (NAME_MAX) を超過しているため再生できません。"}` を返却する

#### Scenario: クライアント切断時の正常終了

- **WHEN** 動画再生中にクライアントが接続を切断（タブ閉じ・シーク）してキャンセルされた時
- **THEN** サーバーは未処理例外として 500 エラーログを記録することなく静かに処理を完了すること

### Requirement: 再生アクセス記録とシーク多重カウント防止

システムは、動画ストリーミング配信とは独立した専用のアクセス記録エンドポイント（`POST /api/videos/{id}/access`）を提供し、動画の再生開始時のみ再生回数をインクリメントしなければならない（SHALL）。シーク操作による部分リクエストで再生回数を増やしてはならない（SHALL NOT）。

#### Scenario: 初回再生開始時のアクセス記録

- **WHEN** クライアントが動画の再生を開始して `POST /api/videos/{id}/access` を呼び出したとき
- **THEN** 該当動画の `AccessCount` が 1 増加し、`LastAccessedAt` に現在日時が記録されること

#### Scenario: シーク操作時のカウント不変

- **WHEN** ユーザーが動画プレイヤー上で再生シークバーを複数回操作したとき
- **THEN** ストリーミング要求のみが発生し、再生回数は増加しないこと

### Requirement: 動画アクセス履歴の個別リセット

システムは、動画カードやプレイヤーから呼び出し可能な再生アクセスリセットエンドポイント（`POST /api/videos/{id}/access/clear`）を提供し、該当動画の再生回数を 0 にクリアしなければならない（SHALL）。

#### Scenario: 再生回数のクリア

- **WHEN** クライアントから `POST /api/videos/{id}/access/clear` が送信されたとき
- **THEN** 該当動画の `AccessCount` が 0 にリセットされ、`LastAccessedAt` が null となること

### Requirement: お気に入り状態の更新および一括更新

システムは、単一動画のお気に入り状態を更新する `PUT /api/videos/{id}/favorite` および、複数選択された動画を一括更新する `POST /api/videos/batch/favorite` を提供しなければならない（SHALL）。

#### Scenario: 単一動画のお気に入りトグル

- **WHEN** ユーザーが動画カードのお気に入りスターアイコンをクリックしたとき
- **THEN** サーバーへ `PUT /api/videos/{id}/favorite` が送信され、お気に入り状態が即座に反転更新されること

#### Scenario: 複数動画のお気に入り一括登録

- **WHEN** 複数動画を選択して一括お気に入り登録を実行したとき
- **THEN** 対象動画の `IsFavorite` が一括で更新されること

### Requirement: 静的ファイル配信によるサムネイル表示

システムは、動画IDに基づくサムネイル画像を `/thumbnails/{id}.jpg` の静的パスとして提供しなければならない（SHALL）。フロントエンドは動画にサムネイルが存在する場合、同静的URLを参照して画像を表示しなければならない（SHALL）。

#### Scenario: サムネイル画像の正常表示

- **WHEN** `thumbnailPath` を持つ動画が描画されるとき
- **THEN** クライアントは `/thumbnails/{id}.jpg` を読み込んでサムネイルを表示すること

#### Scenario: サムネイル未生成動画のプレースホルダー表示

- **WHEN** `thumbnailPath` が null の動画が描画されるとき
- **THEN** 代替プレースホルダー（「No Thumbnail」）が表示されること

### Requirement: モバイル常設キーワード検索欄

システムは、モバイル画面のヘッダー直下に常設のキーワード入力欄を提供し、フリーワード部分一致および `tag:xxx` 形式の DSL 検索に即時対応するインクリメンタル検索機能、ならびにワンタップ入力消去（クリア）コントロールを提供しなければならない（SHALL）。

#### Scenario: モバイル常設検索欄でのキーワード入力

- **WHEN** ユーザーが検索欄に文字列を入力した時
- **THEN** 入力文字に基づき対象動画が即座に絞り込まれ、クリアボタン（✕）が表示されること。

### Requirement: モバイル表示・ソート設定シート

システムは、モバイル画面において、並び替え基準（ファイル更新日【初期値】、TBVM登録日、ファイル名、ファイルサイズ、再生回数、再生時間）、昇順/降順、サムネイル表示切り替え、および読み込みモード（ページング vs 順次追加読み込み）を指先で容易に変更可能なスライド式設定シートを提供しなければならない（SHALL）。

#### Scenario: 設定シートでのファイル更新日時ソートの指定

- **WHEN** モバイルユーザーが表示設定シートを開き、並び替え基準に「ファイル更新日」を選択したとき
- **THEN** 現在の表示モードにかかわらず、動画のファイル更新日時に従って一覧が即座に並び替えられること

#### Scenario: 設定シートでの並び替え条件変更

- **WHEN** ユーザーが表示設定シートを開き、並び替え基準や昇順/降順を変更した時
- **THEN** 現在の表示モード（2列グリッドまたはスリムリスト）にかかわらず、指定した順序で即座に一覧が並び替えられること。

### Requirement: モバイル全画面プレイヤーおよび連続視聴ナビゲーション

システムは、モバイル端末における動画再生時、画面余白を排除した全画面没入型プレイヤーを提供し、一覧画面に戻ることなく前後の動画へシームレスに切り替えて再生できる連続視聴ナビゲーションコントロールを提供しなければならない（SHALL）。また、端末の横画面（ランドスケープ）への回転時に自動で横全画面表示へ追従しなければならない（SHALL）。

#### Scenario: モバイルでの動画タップによる全画面再生開始

- **WHEN** モバイル一覧上で動画サムネイルまたはタイトルをタップした時
- **THEN** 画面全体を覆うプレイヤーが起動し、対象動画のストリーミング再生が即座に開始されること。

#### Scenario: 前後の動画へのシームレス移動

- **WHEN** プレイヤー表示中に「次の動画」または「前の動画」ボタンをタップした時
- **THEN** 一覧に戻ることなく、現在フィルタ・ソートされている動画順に従って対象の動画が切り替わり再生されること。

#### Scenario: ランドスケープ表示への追従

- **WHEN** モバイル端末を横向きに回転させた時
- **THEN** プレイヤーが画面アスペクト比に合わせて最大化表示されること。

### Requirement: モバイル各種子画面モーダルの最適化表示

システムは、統計・おすすめ動画、一括インポート/エクスポート、自動適用ルール管理、スマートフォルダ保存、動画へのタグ付与、および一括タグ操作の各モーダルダイアログを、モバイル画面幅（< 640px）において画面外への突き抜けや操作不能を起こすことなく閲覧・実行できるよう最適化表示しなければならない（SHALL）。

#### Scenario: モバイルでの各種管理モーダル起動と操作

- **WHEN** モバイル端末においてメニューまたは動画操作から各種子画面モーダルを開いた時
- **THEN** 画面幅に収まるスクロール可能なモーダルとして描画され、フォーム入力およびアクション実行が完結できること。

### Requirement: モバイルセーフエリアおよびダイナミックビューポート対応

システムは、モバイルブラウザのアドレスバー開閉に伴う画面高変動（Dynamic Viewport Height / 100dvh）およびノッチ・ホームインジケーター（safe-area-inset）を考慮したレイアウトを適用し、主要操作要素において最低 44x44 ピクセルのタッチ領域を確保しなければならない（SHALL）。

#### Scenario: アドレスバー開閉時のレイアウト維持

- **WHEN** モバイルブラウザでスクロールやアドレスバーの伸縮が発生した時
- **THEN** 画面最下部の一括操作バーやコンテンツが画面外に押し出されたり隠れたりせず、100dvh 内に正常に収まること。

#### Scenario: タッチターゲットのアクセシビリティ

- **WHEN** モバイル画面上でお気に入りボタン（★）や再生ボタン、閉じるボタンをタッチ操作した時
- **THEN** 44x44 ピクセル相当のタップ領域により、隣接要素の誤タップなく確実に意図した操作が反応すること。

### Requirement: モバイルヘッダーからの即時ディレクトリ同期

システムは、モバイルメイン画面のヘッダーに配置された同期ボタンからの要求を受け付け、バックグラウンドでのディレクトリ同期を実行し、実行中アニメーション表示および完了後の自動最新化を行わなければならない（SHALL）。

#### Scenario: モバイルヘッダーでの同期ボタンタップ

- **WHEN** モバイルヘッダーの同期ボタンをタップした時
- **THEN** 同期APIが呼び出され、アイコンが回転アニメーション状態となり、完了時に最新の動画一覧データへ更新されること。

### Requirement: 動画一覧のファイル更新日による並び替え

システムは、Web UI のデスクトップツールバーおよび動画一覧APIにおいて、動画ファイルの最終更新日時（`fileModifiedAt`）を既定（初期値）のソートキーとする昇順および降順の並び替え機能を提供しなければならない（SHALL）。選択肢の順序は「ファイル更新日（初期値）」、「TBVM登録日」、「ファイル名」、「ファイルサイズ」、「再生回数」、「再生時間」の順で提供しなければならない（SHALL）。データベース上で `FileModifiedAt` が未設定の古いレコードが存在する場合、システムのTBVM登録日時（`CreatedAt`）を安全にフォールバックとして採用し、ソート順の破綻を防止しなければならない（SHALL）。

#### Scenario: デスクトップツールバーでの更新日時ソート選択

- **WHEN** ユーザーがデスクトップツールバーの並び替えドロップダウンから「ファイル更新日」を選択したとき
- **THEN** 動画一覧が各動画のファイル最終更新日時の降順（既定）または昇順に従って再レンダリングされること

#### Scenario: 更新日時未設定レコードのフォールバック整列

- **WHEN** 一部の動画レコードで `FileModifiedAt` が未設定の状態で「ファイル更新日」ソートが実行されたとき
- **THEN** 当該レコードはシステムTBVM登録日時（`CreatedAt`）で代用されて整列され、エラーや未定義順序とならないこと

### Requirement: 動画一覧および検索結果におけるタグ情報の一括取得

システムは、動画一覧 API（`GET /api/videos`）および検索 API（`GET /api/videos?q=...`）において、動画ごとに個別のタグ取得クエリを発行（直列 N+1 クエリ）してはならず（SHALL NOT）、対象となる全動画のタグ情報を単一の一括クエリで取得し、メモリ上で各動画レコードへ結合して返却しなければならない（SHALL）。

#### Scenario: 複数動画の一括タグ結合返却

- **WHEN** データベースにタグが紐付いた複数の動画が存在する状態で動画一覧 API が要求されたとき
- **THEN** 直列クエリによる遅延なく、各動画に正しいタグ情報（Id, Name, ColorCode, ParentId）が付与された JSON 配列が返却されること

#### Scenario: タグ未紐付け動画が混在する場合の一括取得

- **WHEN** タグが付与された動画とタグ未付与（0件）の動画が混在するライブラリ一覧が要求されたとき
- **THEN** タグ未付与の動画は空配列（`tags: []`）となり、タグ付き動画には正確にタグが紐付いて全件が返却されること

#### Scenario: 0件時の安全な一括取得

- **WHEN** 検索条件に一致する動画が 0 件の状態で検索 API が呼び出されたとき
- **THEN** タグ取得の一括クエリでエラーや例外が発生せず、空配列（`[]`）が即座に返却されること

### Requirement: サムネイル画像の遅延読み込みとブラウザ負荷軽減

フロントエンド（Web UI）は、デスクトップおよびモバイルにおけるグリッド表示およびリスト表示のすべての動画サムネイル画像要素において、遅延読み込み属性（`loading="lazy"`）および非同期デコード属性（`decoding="async"`）を適用し、ビューポート外の画像リクエストによるネットワーク・I/O 負荷を抑制しなければならない（SHALL）。

#### Scenario: ビューポート外サムネイルの遅延ロード

- **WHEN** ユーザーが動画ライブラリ画面を開いたとき
- **THEN** 画面初期表示領域外にある動画カードのサムネイル画像は即座にリクエストされず、スクロール等で表示領域に近づいた時点で順次読み込まれること

### Requirement: ストリーミングエラー時のフロントエンド詳細通知とオーバーレイ表示

フロントエンド（Web UI）は、動画プレイヤー（`<video>`）におけるストリーミング再生エラー（`@error`）を検知した際、ストリーミングエンドポイントへ非同期リクエストを発行してステータスコードおよびエラーレスポンスを解析しなければならない（SHALL）。ファイル名長制限（`FILE_NAME_TOO_LONG`）を検知した場合は、赤色トースト通知を表示するとともに、プレイヤー画面領域の中央にエラーオーバーレイを表示し、ファイル名が Linux の 255 バイト制限を超過している旨、該当ファイルのパス、および「ファイルパスをコピー」ボタンを表示して AI File Renamer 等での短縮リネームを案内しなければならない（SHALL）。また、物理ファイル不在（HTTP 404 `FILE_NOT_FOUND`）を検知した場合は、「動画ファイルが見つかりません」を含む赤色エラートースト通知およびプレイヤー内エラーオーバーレイ（対象ファイルパス表示・スキャン同期実行ボタン・閉じるボタン）を表示しなければならない（SHALL）。その他のストリーミングエラー発生時にもエラートースト通知を表示しなければならない（SHALL）。

#### Scenario: FILE_NAME_TOO_LONG発生時のトースト通知とプレイヤーオーバーレイ表示

- **WHEN** ユーザーが動画一覧から Linux 255バイト制限超過の動画をクリックして再生を開始し、ストリーミングが HTTP 422 で失敗した時
- **THEN** 画面上に「⚠️ 再生エラー: ファイル名が Linux の 255 バイト制限を超過しています」の赤色トースト通知が表示され、プレイヤー中央に「再生できません / ファイルパスをコピー」を含むオーバーレイメッセージが表示される

#### Scenario: 物理ファイル不在（HTTP 404）発生時のエラートースト通知とオーバーレイ表示

- **WHEN** スキャン実行前に削除または移動された動画をユーザーがクリックして再生を開始し、ストリーミングが HTTP 404 で失敗した時
- **THEN** 画面上に「動画ファイルが見つかりません」を含む赤色エラートースト通知およびプレイヤー中央のエラーオーバーレイ（ファイルパスとスキャン同期実行導線を含む）が表示されること

#### Scenario: 通常のエラー発生時のトースト通知

- **WHEN** ネットワーク切断やサーバー異常等で通常のストリーミングエラーが発生した時
- **THEN** 画面上に適切なエラー内容のトースト通知が表示される

### Requirement: 動画一覧の非同期ロード中およびスキャン中におけるスピナー表示と Zero-State 誤表示防止

フロントエンド（Web UI）は、動画一覧の非同期データ取得（初回ロード時、再読み込み時）を実行中、コンテンツ領域の中央にスピナーおよび「動画を読み込み中...」のテキストを表示しなければならない（SHALL）。データ取得実行中（`isLoadingVideos === true`）またはディレクトリ同期実行中（`isScanning === true`）の間は、動画件数が 0 件であっても「動画が見つかりませんでした」という Zero-State 画面を表示してはならない（SHALL NOT）。データ取得および同期が完了した時点で取得件数が 0 件である場合のみ Zero-State 画面を表示しなければならない（SHALL）。また、Zero-State 画面にはユーザーが即座に操作を再開できるよう、「ディレクトリ同期を実行する」ボタンおよび（検索クエリ入力時）「検索条件をクリアする」ボタンを提供しなければならない（SHALL）。

#### Scenario: 初回ロード中のスピナー表示と Zero-State 抑止

- **WHEN** ユーザーが Web UI にアクセスし、動画一覧データ取得リクエストが実行中であるとき
- **THEN** 「動画が見つかりませんでした」が表示されず、画面中央にスピナーと「動画を読み込み中...」が表示されること

#### Scenario: ディレクトリ同期実行中（isScanning）の Zero-State 抑止

- **WHEN** 初回ロード等で動画が 0 件であり、バックグラウンド同期（`isScanning === true`）が実行中であるとき
- **THEN** 「動画が見つかりませんでした」が表示されず、同期中インジケータが表示されること

#### Scenario: データ0件時の Zero-State 正常表示と回復導線

- **WHEN** 動画一覧データ取得および同期が完了し、動画件数が 0 件であるとき
- **THEN** スピナーが非表示となり、「動画が見つかりませんでした」とともに「ディレクトリ同期を実行する」ボタンが表示されること

#### Scenario: 検索結果0件時の検索クリアボタン表示

- **WHEN** 検索キーワードを入力して検索が完了し、該当動画が 0 件であったとき
- **THEN** 「動画が見つかりませんでした」とともに「検索条件をクリアする」ボタンが表示され、クリックで検索バーがリセットされて全件一覧が再取得されること

### Requirement: 検索・絞り込み・ページ切り替え時の一覧オーバーレイ・スピナー表示と多重クリック抑止

フロントエンド（Web UI）は、既存の動画一覧が表示されている状態で、検索キーワード入力、タグ絞り込み、お気に入り切り替え、スマートフォルダ切り替え、ソート順変更、またはページ切り替えによる非同期データ再取得が発生した場合、既存の一覧表示を維持したまま一覧領域全体に半透明オーバーレイ（クリック遮断付き）および中央スピナーを表示しなければならない（SHALL）。また、検索バー内のアイコンを回転スピナー表示に切り替えなければならない（SHALL）。オーバーレイ表示中は背後の動画カードやボタンのクリック操作を遮断（`pointer-events-auto`）しなければならない（SHALL）。非同期通信が完了したとき、オーバーレイとスピナーを解除し、最新の動画一覧を表示しなければならない（SHALL）。

#### Scenario: 検索実行時の半透明オーバーレイとスピナー表示

- **WHEN** 動画一覧が表示されている状態で、ユーザーが検索キーワードを入力して非同期通信が開始されたとき
- **THEN** 既存の一覧の上に半透明オーバーレイと中央スピナーが表示され、検索バーのアイコンがスピナー表示となること

#### Scenario: オーバーレイ表示中の背後操作の抑止

- **WHEN** 一覧領域に半透明オーバーレイが表示されているとき
- **THEN** 背後の動画カードやボタンをクリックしても反応せず、多重リクエストや予期せぬ画面遷移が発生しないこと

#### Scenario: 検索完了時のオーバーレイ解除と結果描画

- **WHEN** 検索クエリの非同期通信が完了したとき
- **THEN** 半透明オーバーレイとスピナーが解除され、検索結果の動画一覧が描画されること

#### Scenario: タグ絞り込み時のオーバーレイ表示

- **WHEN** ユーザーがタグをクリックして一覧の絞り込み非同期通信が開始されたとき
- **THEN** 一覧領域に半透明オーバーレイとスピナーが表示され、通信完了後に絞り込み結果が表示されること

### Requirement: 連続操作時のレースコンディション抑止と最新リクエスト維持

フロントエンド（Web UI）は、検索キーワード入力やタグ切り替え等の非同期リクエストが短時間に連続して発生した場合、各リクエストに単調増加の一意なリクエストIDを付与しなければならない（SHALL）。先行リクエストの応答が遅延して後続リクエストよりも後に到着した場合、その古い応答を破棄して最新リクエストの結果のみを画面に反映しなければならない（SHALL）。また、先行リクエストが完了・破棄された時点で後続リクエストがまだ通信中である場合、ローディング状態（スピナーおよびオーバーレイ）を解除してはならず（SHALL NOT）、最新リクエストの完了時までローディング表示を継続維持しなければならない（SHALL）。

#### Scenario: 連続検索時の遅延古いレスポンス破棄

- **WHEN** ユーザーが「A」と入力した直後に「AB」と入力し、「A」の応答が「AB」の応答より遅れて到着したとき
- **THEN** 「A」の検索結果は破棄され、画面には「AB」の検索結果のみが表示されること

#### Scenario: 連続操作時のローディング状態の途切れなき継続

- **WHEN** リクエスト1の通信中にリクエスト2が送信され、リクエスト1の処理が先に完了したとき
- **THEN** リクエスト1完了時点でスピナーやオーバーレイが消去されず、リクエスト2が完了するまでローディング表示が途切れず継続すること

### Requirement: 動画一覧取得エラー時の Error-State 表示と再試行導線

フロントエンド（Web UI）は、動画一覧取得 API 通信が失敗（HTTP 5xx、4xx、ネットワーク切断、タイムアウト等）した場合、スピナーを安全に解除し、画面中央にエラーメッセージ、障害内容、および「再試行」ボタンを表示しなければならない（SHALL）。また、エラー発生時は詳細なログ（リクエストURL、HTTPステータス等）をブラウザコンソールに出力し、トースト通知を表示しなければならない（SHALL）。「再試行」ボタンがクリックされた場合、再度 `fetchVideos()` を実行してデータの再取得を試行しなければならない（SHALL）。

#### Scenario: 通信エラー時のエラー画面表示と再試行ボタン

- **WHEN** 動画一覧取得 API が HTTP 500 やネットワーク切断で失敗したとき
- **THEN** スピナーが解除され、「動画の取得に失敗しました」というメッセージと「再試行」ボタンが表示され、Zero-State や空画面で放置されないこと

#### Scenario: 再試行ボタン押下による再リクエスト成功

- **WHEN** エラー画面でユーザーが「再試行」ボタンをクリックしたとき
- **THEN** 再びローディングスピナーが表示され、API リクエストが再送されること
