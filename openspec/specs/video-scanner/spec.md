# video-scanner Specification

## Purpose

ホストOS上の動画ディレクトリを再帰的に走査して新規動画を即座にデータベースへ登録し、バックグラウンドの非同期パイプライン（FFmpeg/ffprobe）により再生時間取得とサムネイル生成を安全・高速に実行する機能を提供する。

## Requirements

### Requirement: ディレクトリ再帰走査とリパースポイント追跡

システムは、環境変数 `VIDEO_DIRS`（`;` 区切り）で指定された全ての動画ディレクトリ配下を再帰的に走査し、対応拡張子（`.mp4`）の動画ファイルを検出しなければならない（SHALL）。また、シンボリックリンクやジャンクションが存在する場合、実体パスを解決して走査を継続しなければならない（SHALL）。指定された一部のディレクトリが存在しない場合は、そのディレクトリのみを警告ログ付きでスキップし、残りのディレクトリの走査を継続しなければならない（SHALL）。全ディレクトリが存在しない場合もエラーとせず 0 件として安全に終了しなければならない（SHALL）。

#### Scenario: 通常ファイルおよびシンボリックリンク配下の動画検出

- **WHEN** スキャン処理が実行されたとき
- **THEN** 各ルートフォルダおよびシンボリックリンク先のすべての `.mp4` ファイルが検出されること

#### Scenario: 存在しないディレクトリの安全走査

- **WHEN** `VIDEO_DIRS` の全ての要素が存在しない状態でスキャンが実行されたとき
- **THEN** 例外終了せず、走査結果 0 件（`Ok 0`）として安全に処理を完了すること

#### Scenario: 複数物理フォルダの動画検出

- **WHEN** `VIDEO_DIRS` に 2 つの物理フォルダ（それぞれ `.mp4` を含む）を指定してスキャンが実行されたとき
- **THEN** 両フォルダ配下のすべての `.mp4` ファイルが検出され DB に登録されること

#### Scenario: 一部ディレクトリが存在しない場合の継続走査

- **WHEN** `VIDEO_DIRS` の 2 件のうち 1 件が存在しない状態でスキャンが実行されたとき
- **THEN** 存在しないディレクトリは警告ログとともにスキップされ、存在するディレクトリの動画のみが登録されて正常終了すること

#### Scenario: ルート間で重複する動画ファイルの単一登録

- **WHEN** `VIDEO_DIRS` の複数要素が同一の物理ファイルを含む（一方が他方の親、または同一パスの重複指定）状態でスキャンが実行されたとき
- **THEN** 同一の物理ファイルは動画として 1 件のみ登録されること

### Requirement: 新規動画の即時DB登録と非同期キュー投入

システムは、新規検出された動画ファイルについて、ファイル情報（ファイル名、相対パス、ファイルサイズ）のみで即座にデータベースへ登録（Duration=0、ThumbnailPath=None）し、メディア処理キューへ非同期投入しなければならない（SHALL）。

#### Scenario: 新規動画の即時DB保存とUIレスポンス

- **WHEN** 新規の動画ファイルがスキャンされたとき
- **THEN** 重いメディア処理を待たずに即座に動画レコードがDBに保存され、一覧画面へ反映可能となること

### Requirement: 既存動画の未処理検出と無限ループ防止

システムは、既存動画の再スキャン時、サムネイルが未作成（ThumbnailPath が None または実ファイルが存在しない）または再生時間が未取得（Duration = 0）の動画を検出し、メディア処理キューへ再投入しなければならない（SHALL）。再生時間が取得済み（Duration > 0）であってもサムネイルが未作成の場合は再処理対象から除外してはならない（SHALL NOT）。また、ffprobeによるメタデータ解析に失敗した動画は既定値（120秒）等で救済してDB更新し、再スキャン時の無限滞留を防止しなければならない（SHALL）。

#### Scenario: 処理失敗レコードの再投入スキップ

- **WHEN** Duration > 0 かつ ThumbnailPath の実ファイルがディスク上に存在する既存動画のとき
- **THEN** ディレクトリ再スキャン実行時にメディア処理キューへ投入されずスキップされること

#### Scenario: メタデータ解析失敗動画の救済フォールバック

- **WHEN** 破損動画等のため ffprobe の再生時間解析が失敗したとき
- **THEN** 既定再生時間（120秒）でメタデータが登録され、以降の無限再試行から除外されること

#### Scenario: サムネイル未作成レコードの再スキャン投入

- **WHEN** Duration > 0 かつ ThumbnailPath が None である既存動画が存在するとき
- **THEN** ディレクトリ再スキャン実行時に当該動画がメディア処理キューへ再投入されること

#### Scenario: サムネイル実ファイル喪失レコードの再生成投入

- **WHEN** DB上 ThumbnailPath が設定されているがディスク上に実ファイルが存在しないとき
- **THEN** ディレクトリ再スキャン実行時に再処理が必要と判定され、メディア処理キューへ投入されること

### Requirement: 2段階シークによるサムネイル生成

システムは、FFmpegによるサムネイル生成時、まず動画の中間地点をシーク位置として入力ファイル指定前に `-ss` を配置する「高速シーク」を試行し、失敗時のみ入力ファイル指定後に `-ss` を配置する「安全シーク」へフォールバックしなければならない（SHALL）。

#### Scenario: 高速シーク成功

- **WHEN** 高速シーク（コンテナシーク）によってサムネイル画像が出力されたとき
- **THEN** 安全シーク（デコードシーク）を実行することなく処理を完了すること

#### Scenario: 高速シーク失敗時の自動フォールバック

- **WHEN** 高速シークによる画像出力が失敗したとき
- **THEN** 自動的に安全シークが実行され、画像が生成されること

### Requirement: メディア処理プロセスの同時実行制御とデッドロック防止

システムは、FFmpegプロセスの同時実行数をセマフォにより1件に制限し、軽量なffprobeプロセスは並行実行しなければならない（SHALL）。また、プロセス実行時は標準出力と標準エラー出力を並行タスクで非同期に読み取り、バッファ溢れによるデッドロックを防止しなければならない（SHALL）。

#### Scenario: FFmpegの逐次実行

- **WHEN** 複数の動画が同時にメディア処理キューに滞留しているとき
- **THEN** FFmpegプロセスは同時に2つ以上起動せず、1件ずつ順次処理されること

#### Scenario: 標準エラーバッファのデッドロック防止

- **WHEN** FFmpegが大量のエラー・警告ログを標準エラー出力へ書き込んだとき
- **THEN** プロセスがハングアップすることなく正常に終了または例外ハンドリングされること

### Requirement: フォルダ名からのフラットタグ自動付与

システムは、動画ファイルのディレクトリ走査時、動画が配置されているフォルダパスの各親・子フォルダ名を抽出し、タグとして自動生成（重複排除、ParentId=None）して動画へ自動付与しなければならない（SHALL）。

#### Scenario: フォルダ名タグの自動紐付け

- **WHEN** `VIDEO_DIR/Touring/2026/sample.mp4` がスキャンされたとき
- **THEN** 「Touring」および「2026」というタグが自動生成され、動画へ紐付けられること

### Requirement: メディア処理の手動停止と安全中断

システムは、バックグラウンドで進行中のメディア処理を停止するAPI（`POST /api/media/stop`）を提供し、処理キューをクリアした上で実行中の外部プロセスを安全に強制終了（Kill）し、キューの永久停止を防がなければならない（SHALL）。

#### Scenario: メディア処理の中断実行

- **WHEN** クライアントから `POST /api/media/stop` が呼び出されたとき
- **THEN** キュー内の待機タスクが全破棄され、実行中のFFmpeg/ffprobeプロセスが直ちに終了すること

### Requirement: サムネイル出力先ディレクトリの自動作成保証

システムは、アプリケーション起動時、ディレクトリ同期スキャン開始時、およびサムネイル生成直前の各契機において、環境変数 `THUMBNAIL_DIR` で指定された出力先ディレクトリの存在を確認し、存在しない場合は自動的にディレクトリを作成しなければならない（SHALL）。

#### Scenario: 起動時におけるサムネイルディレクトリの自動作成

- **WHEN** `THUMBNAIL_DIR` で指定されたディレクトリが存在しない状態でアプリケーションが起動されたとき
- **THEN** ディレクトリが自動作成され、静的ファイル配信ルートが無効化されることなく正常に起動すること

#### Scenario: サムネイル生成直前におけるディレクトリの確実な存在

- **WHEN** サムネイル生成処理が呼び出されたとき
- **THEN** 出力先親ディレクトリが自動的に作成・確保され、ffmpeg の出力ファイル書き込みエラーが発生しないこと

### Requirement: 動画ファイル更新日時の取得・保存とバックフィル

システムは、動画ファイルのディレクトリ走査時、ファイルシステムから動画ファイルの最終更新日時（`LastWriteTimeUtc`）を取得し、新規動画登録時にデータベースへ保存しなければならない（SHALL）。また、既存動画の走査時においてデータベースのファイル更新日時が未設定（NULL）または実ファイルの最終更新日時と乖離している場合、データベースの値を自動的に最新の日時で更新（バックフィル）しなければならない（SHALL）。

#### Scenario: 新規動画スキャン時の更新日時記録

- **WHEN** 新規動画ファイルがディレクトリ走査で検出されたとき
- **THEN** 当該ファイルの最終更新日時が取得され、動画レコードの `FileModifiedAt` に記録されること

#### Scenario: 既存動画スキャン時の未設定日時の自動バックフィル

- **WHEN** データベース上の `FileModifiedAt` が未設定である既存動画が存在するとき
- **THEN** ディレクトリ同期実行時に実ファイルの最終更新日時が読み取られ、データベースレコードが自動更新されること

### Requirement: 動画ディレクトリ設定の必須化と区切り規則

システムは、動画ディレクトリの指定に `VIDEO_DIRS` のみを使用し、旧 `VIDEO_DIR` を参照してはならない（SHALL NOT）。`VIDEO_DIRS` は `;` で区切り、各要素の前後の空白と空要素を無視しなければならない（SHALL）。有効な要素が 1 件も得られない場合（未設定・空文字・空白のみ・`;` のみ）、またはフォルダ名を持たないパス（`D:\` や `/`）が含まれる場合、スキャン要求はエラーとして設定例（例: `VIDEO_DIRS=D:\Anime;F:\Movie`）を含む明確なメッセージを返さなければならない（SHALL）。旧 `VIDEO_DIR` のみが設定されている場合、廃止の旨と `VIDEO_DIRS` への移行案内をメッセージに含めなければならない（SHALL）。

#### Scenario: VIDEO_DIRS 未設定時の明確なエラー

- **WHEN** `VIDEO_DIRS` が未設定または空白のみの状態でスキャンが要求されたとき
- **THEN** 0 件成功として扱われず、設定例を含む `VIDEO_DIRS` の設定が必要である旨のエラーが返ること

#### Scenario: 旧 VIDEO_DIR のみ設定された場合

- **WHEN** `VIDEO_DIR` のみが設定され `VIDEO_DIRS` が未設定の状態でスキャンが要求されたとき
- **THEN** `VIDEO_DIR` は参照されず、旧変数が廃止された旨と `VIDEO_DIRS` への移行案内メッセージを伴うエラーとなること

#### Scenario: 空要素と余白の無視

- **WHEN** `VIDEO_DIRS` が `" D:\A ;; D:\B ;"` のように空要素・余白を含むとき
- **THEN** `D:\A` と `D:\B` の 2 件のみが走査対象として扱われること

#### Scenario: ドライブ直下の拒否

- **WHEN** `VIDEO_DIRS` に `D:\`（ドライブ直下）または `/` が含まれる状態でスキャンが要求されたとき
- **THEN** 走査は行われず、フォルダ名を持たないパスは指定できない旨のエラーが返ること

### Requirement: ルートフォルダ名とサブフォルダ名のタグ自動付与

システムは、動画が属する各ルートフォルダの名前（最終パス要素）と、ルートからの相対サブフォルダ名を、動画に自動的にタグとして作成・付与しなければならない（SHALL）。異なるルートで同名（大文字小文字を区別しない）のフォルダは 1 つのタグに統合しなければならない（SHALL）。また、動画が複数のルートに包含される（入れ子ルート）場合、所属するすべてのルート名および相対サブフォルダ名のタグを付与しなければならない（SHALL）。既存動画の再スキャン時も、不足しているタグがあれば安全に追加付与しなければならない（SHALL）。

#### Scenario: ルート名タグの付与

- **WHEN** `VIDEO_DIRS=D:\Anime;F:\Movie` で `D:\Anime\S1\ep1.mp4` が走査されたとき
- **THEN** 当該動画にタグ `Anime` と `S1` が付与されること

#### Scenario: 同名ルートのタグ統合

- **WHEN** 異なる親を持つ `D:\x\Clips` と `F:\y\clips` が `VIDEO_DIRS` に含まれるとき
- **THEN** 両ルート配下の動画に同一の 1 つのタグ `Clips`（既存タグがあればそれ）が付与され、タグが重複作成されないこと

#### Scenario: 入れ子ルートでの全ルートタグ付与

- **WHEN** `VIDEO_DIRS=D:\Anime;D:\Anime\Special` のように包含関係のルートが指定され `D:\Anime\Special\ova.mp4` が走査されたとき
- **THEN** 指定順序に関わらず、タグ `Anime` および `Special` の双方が付与されること

#### Scenario: 既存動画へのルート名タグの追記

- **WHEN** 既に DB に登録済みの動画（旧仕様等でルート名タグ未付与）に対して再スキャンが実行されたとき
- **THEN** 動画レコードの重複登録は行われず、現在のルート名タグが不足している場合にのみタグの紐付けが追加されること

### Requirement: ファイルパス正規化と重複登録防止

システムは、スキャン対象ファイルのパスを正規化（末尾区切り除去、絶対パス化、Windows 環境における大文字小文字差異の同一視）してデータベースの `FilePath` と照合しなければならない（SHALL）。大文字小文字の表記揺れやパス指定方法の違いによって同一物理ファイルが別レコードとして多重登録されてはならない（SHALL NOT）。

#### Scenario: 大文字小文字表記揺れの再スキャン

- **WHEN** `d:\videos\a.mp4` として登録済みの環境で、`D:\VIDEOS` を指定して再スキャンが実行されたとき
- **THEN** 新規レコードとして追加されず、既存の動画レコードとして認識されること

### Requirement: スキャン失敗時の UI エラー詳細通知

フロントエンド（Web UI）は、スキャン同期 API の呼び出しが失敗した際、固定メッセージのみを表示するのではなく、API が返却したエラー詳細内容および設定例をトースト通知に表示し、利用者が画面上で原因と対処法を確認できるようにしなければならない（SHALL）。

#### Scenario: 設定不備トーストの表示

- **WHEN** `VIDEO_DIRS` 未設定等の理由によりスキャン API が 500 エラーを返却したとき
- **THEN** トースト通知に「スキャン同期に失敗しました。」とともに、API から受信した設定例を含む詳細エラーメッセージが表示されること
