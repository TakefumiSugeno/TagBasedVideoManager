# Applyテストレビュープロトコル（トートロジー・偽装テスト告発型）

対象: テストタスクの成果物（テストコード・テスト実行結果・カバレッジレポート）
レビュアー: QA Reviewer Agent

> [!IMPORTANT]
> C0/C1カバレッジ数値やテスト全件Pass、skip放置ゼロなどの機械的検証は `verify-gate.ps1` が自動判定します。
> レビュアーは言葉による追認を排し、以下の**「トートロジー告発」「甘いアサーション検出」「ミューテーション思考」**に具体的に回答してください。

---

## 1. トートロジーテスト（実装式のコピペ）の告発

**担当: QA Reviewer Agent**

1. **期待値計算のコピペ検証**:
   - テストコードの期待値（expected）を計算するロジックに、**「プロダクションコードと同じ計算ロジック・正規表現・アルゴリズム」がそのままコピペされている箇所**はないか？
   - 期待値は具体的な固定リテラル値（具体的な数値・文字列・オブジェクト）で検証されているか？
2. **アサーションなし・形式的テストの告発**:
   - 単に「例外が出ずに実行が完了したこと」だけを確認し、戻り値や副作用（DB・状態変化）の内容を実質的にアサートしていないテストはないか？

## 2. 甘いアサーション・無意味なモックの告発

**担当: QA Reviewer Agent**

1. **モック過多による空洞化**:
   - 外部I/Oではなく、テスト対象自身の内部ロジックやプライベートメソッドをモック化して、「モックした戻り値をそのまま検証するだけ」の形骸化したテストになっていないか？
2. **あいまいアサーションの排除**:
   - `toBeTruthy()` や `not.toBeNull()`、型チェックだけで済ませており、具体的な値の内容を検証していない甘いアサーションを指摘せよ。

## 3. ミューテーション思考（バグのすり抜け検証）

**担当: QA Reviewer Agent**

1. **条件反転テスト思考**:
   - もしプロダクションコードの主要な `if` 条件を反転（`>` を `<` に、`true` を `false` に）させたり、戻り値に `+ 1` を加えた場合、**このテストコードは確実に失敗（Red）するか？**
   - 実装を破壊してもすり抜けて Pass してしまう「甘いテスト（死角）」を1箇所特定せよ。

## 4. フレーキー要因・環境依存の摘出

**担当: QA Reviewer Agent**

1. **フレーキー要因の有無**:
   - 固定秒数の `sleep` 待機、テスト間の状態共有、テスト実行順序への依存、現在時刻 `DateTime.Now` / `Date.now()` の直参照がないか？
